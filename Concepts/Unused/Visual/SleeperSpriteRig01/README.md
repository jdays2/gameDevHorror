# Спящий: подготовка спрайтов 01 — остановлено владельцем

Текущий выбор владельца: отдельный дизайн и его доработка отложены. Используется [копия Сталкера с другой палитрой](../../../Used/Sleeper/StalkerPlaceholder01/README.md) и новые звуки. Ниже — историческое состояние пробы; её результаты не подключены к заглушке. Экспериментальные Editor-файлы вынесены из Assets.

2026-10-17. **Готовых атласов нет: 0 из намеченных 64 кадров. AI, prefab и сцены Спящего не создавались.** Ни один новый рисунок не утверждён. Этот каталог сохраняет попытки генерации и черновик анимационного инструмента для продолжения, не заменяет производственные ассеты.

## Требования владельца

Один глаз; три опоры; три короткие створки пасти с разрезами в закрытии. Зубы, суставы, мышцы и пятна крови постоянны между кадрами. При атаке — резкий выпад вперёд. Спящий издаёт мембранное дыхание; отдельный вскрик только при пробуждении, возможны вскрики от попадания и разрыва при смерти. Пробы звука — [SleeperVoice01](../../Audio/SleeperVoice01/README.md).

## Что произошло с генерацией

Два запроса атласа частей через встроенный imagegen не дали изображения: сервис отклонил выход. Затем отдельная правка цельного спрайта завершилась, но [результат](Sources/master-extraction-rejected.png) снова изменил глаз и оставил непрозрачную подложку/ореол. Он отвергнут внутри задачи и **не используется**. Промпты и происхождение сохранены; CLI, иной провайдер или обход фильтра не использовались.

Запрошено явное разрешение владельца на программное удаление фона и подготовку существующего рисунка для скелета: инструкция инструмента imagegen требует явного указания для такой обработки. На момент сохранения ответ ещё не получен. Исходные изображения не чистились, не перекрашивались и не разрезались. Это текущий блокер производства кадров, а не художественное одобрение прежней анатомии.

## Подготовленный способ анимации

[AuthoringDrafts](AuthoringDrafts) содержит два Editor-черновика вне Assets: шестикостный mesh-rig существующего тела и три створки на фиксированных шарнирах с шестью прикреплёнными зубными полигонами. Эти файлы временно компилировались в Editor для проверки формул, затем вынесены из импортируемого проекта, пока нет пригодного источника. Runtime остаётся 2D; геометрия предназначена только для офлайн-запекания целых RGBA-кадров. Это не возврат эксперимента с объёмными тенями.

| Клип | Намечено кадров | Назначение |
|---|---:|---|
| sleep | 8 | Дыхание внутренней мембраны, покой опор |
| wake | 10 | Раскрытие глаза/створок и пробуждение |
| walk | 16 | Три поочерёдных переноса, минимум две опоры |
| attack | 12 | Подготовка, задний толчок, переднее приземление, восстановление |
| hit | 6 | Короткая реакция на урон |
| death | 12 | Разделение тех же частей и оседание без дублирования целого тела |

Предложен кадр 512×512, общий canvas 2.8 units, pivot .5/.5, source 1024×1536. Длины/скорости здесь — настройки художественной пробы, не утверждённый баланс боя. Перемещение root хранится отдельно: будущий motor должен быть единственным владельцем выпада, нельзя одновременно прибавлять его в motor и в рисунке.

[Проверка C# формул](pose-formula-check.json) показала минимум две опоры при ходьбе и одну при выпаде; ошибки длины/контакта порядка 10⁻⁷ units. **Это не проверка готовой анимации:** кадры не рендерились, складки/стыки/альфа, движение на поворотах, зубные пересечения и видимость створок пока не проверены. Особенно важно осмотреть суставы мягкого mesh-скининга и не принять отсутствие IK-clamp за отсутствие растяжения кожи.

Для продолжения после разрешения: подготовить RGBA без старой головы, сохранив когти; восстановить только эти два Editor-файла с их meta; передать готовый источник в `SleeperSpriteBaker.Bake`, подключить `SleeperJawBakeSource.Apply(pose.jawProgress, pose.eyeProgress)` через callback; получить все атласы и отдельно проверить закрытие пасти, каждую опору и реальный игровой размер. До такой проверки не переносить семейство в Used и не назначать в игровой prefab.
