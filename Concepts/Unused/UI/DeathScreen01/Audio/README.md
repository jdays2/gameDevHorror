## Рекомендация и ограничение стиля

Для оценки предлагается02. Сравнение реальных аудиофайлов тем же проектным CLAP показывает более устойчивую органоподобную составляющую в основной части02 (0.568/0.527), чем01 после вступления (0.388/0.387). При этом сохраняются ассоциации с bright lead/rock-like и низким пульсом. Оба результата остаются только кандидатами;02 не объявлен утверждённым попаданием в звук проекта. Если такая окраска слышится лишней, направление надо уточнить до расширения.

Промпт не считается доказательством результата: у02 ориентировочная периодичность около60–61BPM, chroma тяготеет к Eb, а не запрошенным F–C/90. Точная гармония и инструменты не транскрибированы. Более медленный темп предлагается для экрана смерти, который передаёт музыку через fade, не в синхронном tonal-mix с паузой.

`style-analysis.json` содержит аудиоизмерения, одинаковый набор текстовых сравнений, окна0/10/20s новых проб и0/10/80s одобренного трека. Это относительные модельные сходства, не вероятности инструментов и не слуховая оценка. **Прямого аудиопрослушивания агентом не было.**

[style_comparison.mp3](Previews/style_comparison.mp3): 0–10s одобренное вступление;10–11s тишина;11–21s начало02;21–22s тишина;22–32s основная часть02. Каждый фрагмент приведён к−23dBFS RMS с80ms краевыми fade; это не LUFS-нормализация и не новая версия принятого трека. Сравнение содержит только материал проекта.

| Экспорт | Длина | Назначение |
|---|---:|---|
| [LastWard02_Intro.wav](Exports/LastWard02_Intro.wav) | 9.54s /457920samples | Начало оригинала, включая300ms перекрытия |
| [LastWard02_Loop.wav](Exports/LastWard02_Loop.wav) | 16s /768000samples | Участок9.24–25.24s, подготовленный для повторения |

Stereo PCM24/48kHz. Исходник MP3 остаётся lossy: конвертация не восстанавливает утраченное качество. На оба экспорта применён один постоянный gain−2.848314dB, без EQ/компрессии/pitch/time stretch.4× true peak: intro−3.000dBTP, loop−4.018dBTP.

Loop стартует на9.24s intro. Последние300ms intro равны первым300ms loop после PCM24; для такого совпадающего сигнала используются взаимодополняющие линейные коэффициенты. Во внутренних последних600ms loop выполнен equal-power переход к реальному pre-roll8.64–9.24s. Следующий первый sample продолжает естественную пару источника: шаг−68.09dBFS, ошибка≤1.65×10⁻⁸. Монтаж технически непрерывен, музыкальная естественность пока не принята.

Длительность16s выбрана по устойчивой области этой пробы, близости chroma/энергии края и локальной периодичности; примерное соответствие четырём медленным тактам — гипотеза, не партитура. Длины паузы42.95/21.333s не копировались.

[Intro+3loops](Previews/last_ward_intro_3loops.mp3) длится57.24s, повторы на25.24/41.24s. В preview запечены fade-in1.4s/fade-out0.8s; исходные экспорты этих fade не содержат. [Стык петли](Previews/last_ward_loop_seam.mp3) и [стык intro](Previews/last_ward_intro_join.mp3) — по4s, переход на2s. Есть PCM24 WAV-версии всех preview.

Стартовый будущий runtime-уровень0.32 (примерно−9.9dB), fade-in1.4s/out0.8s — предложения для оценки. User Master/Music остаются верхними регуляторами; музыка смерти/UI независимы от world-fade. Это не настройки Unity и не исправление BUG-053.

## Воспроизведение

Скрипты принимают `--analysis-root <outputs/audio-reference-analysis>`, где уже отдельно установлены numpy/scipy/librosa/soundfile/imageio_ffmpeg/onnxruntime/tokenizers и проектная CLAP-модель. Runtime/веса не являются контентом и сюда не копировались.

```text
python analyze_audition.py --analysis-root <absolute-path-to-outputs/audio-reference-analysis>
python process_audition.py --analysis-root <absolute-path-to-outputs/audio-reference-analysis>
```

`analyze_audition.py` использует неизменённое начало существующего `clap_semantics.py` до списка входов: те же веса/метки/features; путь к его источнику задаёт analysis-root. `process_audition.py` создаёт только экспорты/preview этой семьи и processing.json. Хеши, lengths, конечность, stereo/PCM24/48k и измерения — [processing.json](processing.json), общая карта — [../provenance.json](../provenance.json).
