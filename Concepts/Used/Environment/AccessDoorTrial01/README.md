# AccessDoorTrial01 · варианты 02

Владелец отклонил пиктограмму карты из первой пробы. Сейчас сравниваются три статичных двухслойных маркировки без текста и значков:

- A-solid-panel: белая панель 3×0.9 unit с непрерывной синей/зелёной рамкой.
- B-striped-panel: белая зона 3×1.5 unit с диагональной П-образной каймой; временно включена на двух дверях.
- C-double-outline: белый П-контур под более узким цветным, 3×1.2 unit; пол внутри остаётся виден.

Ни один вариант не утверждён художественно. На H-P используется зелёный цвет, на H-O3 — синий. PNG содержат белый RGB и альфа-маску; цвет задаёт SpriteRenderer. Основа — матовая слегка тёплая белая краска (.78/.79/.76), освещаемая обычным FlatLit. Нет свечения, теневого объёма или нарисованной падающей тени. Тонкая фактура взята из действующей разметки пола. Геометрические SVG поясняют контуры; точную растеризацию и фазу полос воспроизводит marking_variants.py, 512 PPU. Он находит Unity-проект при запуске из этой папки и экспортирует только шесть масок пробы, без изменения сцены или прежней разметки.

card-stencil.png/svg и prepare.py — исторический отклонённый первый вариант; значок больше не имеет ссылок из сохранённых сцен/префабов/assets. Исторический PNG остаётся в Art как неиспользуемый ресурс, исходник сохранён здесь. prepare.py также воспроизводит короткие звуки считывателя, которые сохраняются: нисходящая пара — отказ, восходящая — доступ. Это офлайн PCM 48 kHz mono с мягкой огибающей; принятые записи движения и остановки двери не изменены. Громкость .32, задержка открытия .24 с, повтор отказа не чаще .8 с. Звуковая оценка остаётся за владельцем.

Промежуточные и действующие источники — provenance.json; размещение и переключение A/B/C — Docs/Guides/MORGUE_ROUTE_TEST.md. Сравнение получено из реального Game View: одна камера, один фонарь, одинаковая позиция игрока, одинаковые кадрирование и масштаб. Процедурная техническая графика, без внешних заимствований и генерации модели.
