# Правила проекта Emergency Shift

## Источник требований

Последнее прямое указание пользователя важнее этого файла. Текущая спецификация — `Docs/SPEC.md`. Перед изменениями прочитать её и `Docs/ARCHITECTURE.md`; после изменений обновить `CHANGELOG.md`, карту файлов и затронутые разделы учебного гайда.

Направление и будущие механики зафиксированы в `Docs/GAME_DIRECTION.md`: survival horror с последующей стрельбой, камера/движение вдохновлены Hotline Miami, пространство раскрывается светом и исследованием. Визуальный диапазон — 2D/2.5D; технический MVP остаётся 2D. Будущие пункты не реализовывать автоматически вне текущей задачи.

Предложенный план этапов и приоритетов — `Docs/MVP_PLAN.md`. Он отделяет первый MVP с фонарём и одним типом монстра от следующего боевого среза. Сохранение после каждой завершённой румы входит в первый MVP. Момент завершения румы и конкретные упрощения отмечены как предложения, а не уже утверждённая реализация. Планирование не является указанием автоматически строить все этапы в текущем запросе.

## Текущий объём

- Unity 6000.6.5f1, C#, URP с 2D Renderer.
- Одна редактируемая сцена: две пустые комнаты, коридор, стены и дверь.
- Игрок — однотонная капсула; WASD; мышь направляет фонарь; F включает и выключает свет; E взаимодействует с близкой дверью. Пистолет/патроны/модули подбираются автоматически в радиусе .65 без требования света, с проверкой стены/закрытой двери.
- Почти полная темнота, один шестиногий негуманоидный сталкер. Есть подкрадывание, следящий зрачок, реакция на свет, укус, поражение игрока и гибель врага с кровью/кусками. В v0.6 добавлен пистолет, коробки патронов, летящие пули и три световых профиля. Художественного окружения, инвентаря и батарейки пока нет. Рабочая мембрана сталкера подключена в v0.8; временные звуки автоподбора — в v0.8.1. Звуки пистолета/материалов подготовлены как кандидаты, Combat Audio Enabled по умолчанию false до оценки.
- UI содержит название, управление, состояние фонаря, подсказку двери, здоровье и поражение с перезапуском по R.
- Позиция и параметры сталкера, изменённые пользователем в Inspector, имеют приоритет над стартовыми значениями кода. В текущей пользовательской группе Stalkers несколько экземпляров; позиции каждого сохранять. Проверенные страх 2.0, задержка 0.33 с. Не сбрасывать их при обновлении кадров/префаба.
- Исправленные ходьба/сжатие сталкера — ориентир следующих анимаций. Правила качества — `Docs/ANIMATION_REFERENCE.md`. Тема локаций остаётся открытой.
- Рабочая палитра сталкера — v09: бледная серо-розовая плоть, холодные лиловые тени, локальная красная кровь. Кремовый костяной пример v08 отклонён. Текстуры в `Art/Stalker/PaleFlesh`, Rect/pivot в `PaletteFrameLayout.json`; все 28 активных кадров/фрагментов сохранены с прежними GUID.
- Живые SortingGroup=1, останки=0. Трупы/куски затемняет `RemainsVisualStyle`, лужи не затемнять вместе с ними. Лужа создаётся сразу при Dead; разлёт кусков через 0.12 с. Не возвращать размытую/полупрозрачную подложку в спрайты.
- Сталкер принят пользователем 14 октября 2026 как первая готовая версия врага первого уровня: движение, свет, атака, гибель, останки и кровь. Это эталон для следующих существ; движение толпы остаётся будущей задачей, пистолет добавлен в v0.6.
- `CreatureGroundShadow2D` теперь использует альфа-силуэт текущего кадра, включая все шесть ног. Чёткие контактная/направленная тени сохранены в префабе/сцене. Общий шейдер `CreatureSilhouetteShadow` обрезает проекцию по лучу/стене, без ShadowCaster2D и изменения света других врагов. Старый мягкий овал отклонён. После смерти проекция скрывается, контактная следует кадру останков.
- В v0.5.2 `FlashlightRangeUpgrade.prefab` повторяемый: каждый новый автоматически подобранный предмет даёт +0.6 дальности/+6° угла, база 4.2/80, пределы игрока 7/110. В сцене четыре находки: пользовательские позиции сохранены, две дополнительные в группе Flashlight upgrades — test path. Repeatable=true разрешает одинаковый ID у разных экземпляров; один физический предмет всё равно однократный. false поддерживает уникальный режим. FlashlightUpgrades суммирует бонусы, вызывает SetOptics; прогресс только в текущем запуске комнаты. Инструкция — Docs/FLASHLIGHT_UPGRADE_GUIDE.md. Старое правило «одинаковый ID всегда один раз» отменено новым запросом.
- Общий дальнейший концепт — `Docs/FLASHLIGHT_AND_LOOT.md`; каталог предметов ScriptableObject, ключ-карты и сохранения пока не реализованы. Для единственного вида лута настройки находятся в компоненте префаба. Будущие пункты не реализовывать автоматически.
- По последней правке пользователя не выводить числовой отчёт об улучшении ни после подбора, ни в подсказке. После автоподбора показывать «Получено: Модуль фонаря», без чисел оптики. Патроны показывают фактически полученное количество. Сам бонус и параметры Inspector сохраняются.
- Пистолет подбирается автоматически, выдаёт 8 патронов; три коробки по 12 в текущей сцене, предел 120. Непоместившийся остаток коробки остаётся на земле. HUD патронов скрыт до HasWeapon. ЛКМ полуавтоматический, 0.3 с, урон 1; без магазина/перезарядки/headshot. R после смерти перезапускает комнату. Пули проверяют путь CircleCast, блокируются стеной/дверью, вызывают существующий TakeDamage/GoreBurst. Фонарь продолжает работать, вспышка не считается защитным лучом. Ключевые настройки — WEAPONS.md.
- ShotVisualProfile: WarmFlash (по умолчанию), ColdTrail, RedPulse; переключение через Preview/Shooting или Visual Profile игрока. Это прототипы цвета/следа, не утверждённая финальная графика. Не генерировать новый рисунок монстра/оружия без задачи. WeaponDemoRecorder только Editor и временный Play-объект; постановку/камеру/выданный запас не сохранять.
- Пользовательская дополнительная четвёртая находка фонаря сохранена при подготовке оружия; не удалять её ради старого числа «три» в историческом отчёте.
- Описание врагов и будущая вариативность разорванных тел — `Docs/ENEMIES.md`. У каждого типа потребуется несколько рисунков/вариантов останков; случайный поворот одной позы этого не заменяет. Новую графику без задачи не генерировать.
- Целевой будущий сценарий — 10–20 активных врагов и накопление крови/частей после их гибели. Он требует отдельной проверки движения группы и Profiler; не заявлять поддержку толпы по тесту одного врага и не создавать толпу автоматически вне задачи.
- Для осмотра крови в стартовой комнате сохранена группа `Test corpses — Stalkers`: четыре статических трупа без AI и коллайдеров. Их пользовательскую расстановку сохранять; не принимать за живых врагов.
- Фонарь v0.2: дальность 4.2, полный угол 80°, слабая ближняя подсветка радиусом 0.65; оба источника переключаются F и отбрасывают тени. `Range` и `Beam Angle` — параметры компонента фонаря; настраивать их, а не обходить компонент ручным изменением внешнего радиуса Light2D.
- Ключи/пароли пока будущие механики; тестовые мигающие лампы уже есть. Тестовая дверь по E без ключа. Предметы улучшения пользователь добавляет из готового префаба; оптику/сталкера при подготовке не сбрасывать.

## Архитектура и сцены

1. Уровень хранится в `.unity`, повторяющиеся объекты — в `.prefab`. Изменения объектов делать в сцене/префабах, сохраняя существующие ручные правки.
2. Не генерировать уровень и UI при старте игры. `PrototypeSceneBuilder` — только первоначальный инструмент редактора. Он должен отказываться перезаписывать уже существующую сцену.
3. Один небольшой `MonoBehaviour` отвечает за одно поведение. Использовать явные ссылки через `[SerializeField]`, назначаемые в Inspector. Не добавлять singleton, глобальную шину событий, DI-контейнер, ECS или универсальный менеджер ради гипотетического будущего.
4. Игровой код — `Assets/EmergencyShift/Scripts`; инструменты редактора — `Assets/EmergencyShift/Editor`. Не ссылаться на `UnityEditor` из игрового кода.
5. Обрабатывать отсутствие устройств ввода. Читать ввод в `Update`, перемещать физическое тело в `FixedUpdate`, камеру — в `LateUpdate`. Скорость по диагонали должна совпадать со скоростью по одной оси.
6. Визуальная тень, физическое столкновение и игровое обнаружение — разные задачи. Свет должен перекрываться стеной и закрытой дверью.
   Непрозрачные стены/двери текущего каркаса используют `Cast and Self Shadow`; источник фонаря смещён на 0.18 и остаётся внутри безопасной области коллайдера. Проверять углы и близкий контакт со стеной. Не сохранять временные тестовые позиции/отключённую физику из Play в сцену.
7. Сохранять `.meta` вместе с ассетами. Не редактировать `Library/PackageCache`, не коммитить `Library`, `Temp`, `Logs`, `UserSettings`.
8. Новую зависимость добавлять, только если она решает текущую задачу; зафиксировать версию и назначение в документации.

## Проверка и отчёт

- Проверить компиляцию в Unity, ссылки компонентов и сохранение сцены.
- В Play Mode проверить WASD, равную скорость по диагонали, столкновения, F, направление луча, E и проход через открытую дверь.
- Проверить свет и UI визуально. Статическое чтение кода не заменяет запуск.
- В `Docs/VALIDATION.md` отличать выполненные проверки от ожидаемых. Не писать «готово/прошло» без наблюдения результата.
- После изменения поведения обновить `SPEC.md` и понятное объяснение для новичка: что изменили, зачем, где увидеть результат.
- Не расширять объём без новой задачи пользователя. ImageGen разрешён для согласованных спрайтов существ. Проверять анатомию, прозрачность, масштаб и нарезку. Равная сетка не гарантирует безопасных границ кадра; корректный рисунок сохранять, исправляя метаданные.
- `StalkerDemoRecorder` существует только для Editor (`UNITY_EDITOR`), без ссылок на UnityEditor в игровом коде. Не сохранять в сцену компонент записи, тестовую подсветку, позиции демонстрации или отключённые компоненты. Сценарное управление записью описывать в отчёте.

## MCP

Репозиторий https://github.com/jdays2/gameDevHorror, origin/main. Исходная история сохранена. Коммитить Assets с .meta, Packages, ProjectSettings и документацию; не включать Unity-кеши, UserSettings, логи, локальную .vscode/MCP-конфигурацию. Не использовать force-push. Текущий прогресс — Docs/PROGRESS.md. Увеличенный Game View может обрезать HUD: сначала Fit Game View, прежде чем менять радиусы взаимодействия.

Unity MCP 10.3.0 используется для проверки редактора, сцены и консоли. Context7 — для документации, когда доступен. Настройки конкретного компьютера и токены не хранить в Git. При недоступном MCP продолжать допустимую работу с исходниками, явно сообщая пределы проверки.

v0.6.1: у вспышки белое ядро, три слоя пламени и четыре искры; яркость держится первые 25% короткого импульса. GoreBurst выпускает восемь кусков с разным импульсом/подлётом через .12 с. GibMotion разделяет координаты пола и условную высоту: после удара быстро останавливается. BloodRuptureBurst — временный веер крови (.36 с), BloodPool остаётся; статические тестовые трупы не анимировать. Новые настройки силы/подлёта находятся в GoreBurst Inspector. Не возвращать медленное скольжение.

## Уточнение текущего контракта v0.6.2

COMBAT_FEEL_PLAN.md — приоритеты света/попаданий/домашней зоны/управления; выполнены, результаты в VALIDATION. Сталкер начинает Dormant, активируется только в домашнем радиусе при видимости, возвращается при выходе за радиус + margin или потере видимости. Home фиксируется в Awake по позиции конкретного экземпляра. Не сбрасывать пользовательские Habitat Radius/расстановку: сейчас есть отдельные радиусы 2 и 2.35, стандарт нового экземпляра 3.2.

Игровой ввод использует Flashlight2D.AimTowards (.075 с/720°/с/dead zone .25); AimAt — явная мгновенная постановка для сценариев/тестов. Оружие/пуля читают фактический угол. CameraFollow2D следует игроку с .18 и не читает мышь. Не добавлять увод/тряску камеры автоматически.

ApplyBulletHit — один урон, малый BloodHitSpray и короткая реакция корпуса; живой враг получает .09 с stagger/небольшой толчок, укус прерывается. Постоянная лужа только в Dead, повторный удар по Dead не дублирует эффект. Тень капсулы от настоящего света дула — PlayerShotShadow2D, ограниченная силуэтная проекция с отсечением стеной/радиусом; не выдавать её за полноценную 3D-тень. MuzzleGlow + TransientGlow заменили острые плоские слои мягкой аддитивной вспышкой. Свет профилей теперь 8/3.6/.16, 7.2/3.4/.14, 9/3.9/.18 (intensity/radius/seconds). Звук P0 следующего отдельного этапа; сложные ранения/ордовый AI вне текущего объёма.

## v0.7 — актуальное решение по темноте

По прямому указанию пользователя туман войны/память карты отменены. Не возвращать маску посещения, копии изученной геометрии или принудительное скрытие рендереров. Нативный URP 2D свет, ambient .002, постоянный отчётливо видимый Boundary guide на 12 стенах/створке. Тени существ и от выстрела сохранены.

Стенд Occlusion playground: четыре раздельных пропа, шесть ламп LocalLamp2D разной яркости, дополнительный территориальный сталкер/патроны за шкафом. Текущих живых экземпляров семь; старую пользовательскую расстановку/радиусы не сбрасывать ради исторического числа пять. Мигающие лампы теперь реализованы; ключи/пароли остаются будущими.

LightObstacles=8 перекрывает свет/LOS/физику; LowObstacles=9 только физику/пули/движение врага/куски. LowBench без ShadowCaster. Низкая поверхность и предметы Z=-.045 над лужами; живой SortingGroup=1 выше останков=0. Лут освещается обычным светом, но v0.8.1 отменяет требование освещения для подбора; маленькие лампы не вызывают страх сталкера. Новые параметры редактировать на LocalLamp2D, не на управляемом Light2D. Сцена/префабы — источник расстановки, без runtime-генерации уровня. Подробности — Docs/LIGHTING_PLAYGROUND.md.

## v0.7.1 — патруль или засада

StalkerPatrol2D на префабе/всех семи экземплярах. Patrol Enabled по умолчанию false: ожидание у Home, активация в прежнем Habitat Radius при LOS. true: мирное блуждание по отдельной world-aligned области Area Size/Offset, .6 скорости, паузы .6–1.8. Редакторские маркеры — StalkerPatrol2DEditor. В примере включён только Cover Stalker — Room B, область3×4. Не сбрасывать пользовательский радиус1.2 этого экземпляра или остальные параметры/позиции. Прямоугольник патруля и круг обнаружения независимы.

Patrolling дописан в конец enum; старые значения сохранены. Контроллер владеет состояниями, компонент патруля только мирной целью/паузой. Погоня/страх/атака/Dead приоритетнее; после потери цели возврат к Home и возобновление выбранного режима. Все пробы учитывают радиус тела/слои8|9. Это местная навигация с ограниченными попытками, не полноценный поиск пути или проверка толпы. Инструкция — Docs/PATROL_GUIDE.md.

## v0.7.2 — последнее правило, отменяет возврат/потерю цели выше

После первой близости+LOS HasAggro остаётся до смерти врага/игрока; урон пулей тоже провоцирует. Detection Radius (старое serialized habitatRadius) теперь вокруг текущего тела и нужен только для первичного обнаружения. Не возвращать домой, не снимать агрессию по расстоянию/LOS/таймеру. Returning оставлен лишь зарезервированным значением enum, код его не выбирает; TargetDead останавливает бой при смерти игрока. Укус требует LOS.

Patrol Enabled — только перемещения до агрессии; выключение останавливает на текущем месте. Use Patrol Area — опциональное ограничение мирных точек; без него короткие шаги от текущей позиции. Никакой привязки погони к области. После неагрессивного испуга мирный режим продолжается с нового места. Основной фонарь может напугать вне радиуса обнаружения, но это само не включает HasAggro. Стены/высокая мебель блокируют обнаружение/свет, низкая мебель только физику.

Новая база и минимальная миграция текущих экземпляров: преследование1.5, отход3.8, страх3.2; пользовательские позиции, Detection Radius, Reaction Delay и флаги/области сохранены. StalkerChasePath2D — ограниченный кэшируемый A* для погони за углами, не общий менеджер/проверка толпы. Подробности — PATROL_GUIDE.md.

Флаер зафиксирован как будущий временный динамический источник отпугивающего света/зона избегания. Сейчас его НЕ реализовывать: ни предмет/бросок, ни учёт LocalLamp2D в страхе. Будущий флаер приостанавливает наступление, не сбрасывает постоянную агрессию.

## Звуковое направление — реализм, 14 октября 2026

По прямому указанию все звуки должны быть реалистичными/физически убедительными ради атмосферы. 2D/спрайты не означают пиксельные бипы, игрушечные хлопки или синтетический выстрел. Пользователь отклонил предыдущие процедурные кандидаты пистолета v0.8.1; не считать их принятыми и не включать автоматически через Combat Audio Enabled. Автоподбор/его временные клики и утверждённая мембрана сталкера сохранены, не переделывать их без отдельной задачи.

WEAPON_SOUND_STUDIES.md и Docs/Audio/WeaponRealism02:4 новых примера оружия и2 отдельных гильз из источников CC0. Это подборка/монтаж реальных записей и одного авторского многослойного дизайна на основе записанного оружия, не наша полевая запись/нейрогенерация. Исходники — публичные MP3-превью; WAV-экспорт не улучшает качество. Источники/авторы/лицензии/SHA сохранять, перед финальным импортом по возможности использовать lossless-оригинал. Новые WAV находятся вне Assets, ссылки/сцена/боевой флаг не изменены. Только пользователь оценивает характер; числовая проверка не означает художественного одобрения.

Падающие/звенящие гильзы — важное требование следующего боевого аудио. Выстрел/попадание/касание пола гильзой должны быть отдельными событиями; материал пола брать в точке приземления. Примеры с записанными отскоками запускать один раз при первом касании, не целиком на каждом контакте. Отдельные варианты/ограниченные каналы, без AudioSource на каждом патроне. В текущей задаче только примеры; физику гильз/новый runtime не добавляли. Платный плагин без нового поручения не использовать.
