Чеклисты изменений/контента выполнять по применимости. Обсуждение само по себе не разрешает рефакторинг. Канонические skills хранятся здесь; копии установлены в ~/.codex/skills. После обновления синхронизировать копии. Не обещать автоматическое срабатывание skills вне области проекта.

Пять перенесённых из SOD skills находятся в `.agents/skills/`: `unity-pipeline`, `unity-package-management`, `ui`, `ui-ugui`, `physics-3d-collision`. Применять их по назначению; 3D PhysX не заменяет диагностику нашей Physics2D. Unity-команды выполнять с явным путём проекта и `--caller plugin --skill <имя>`.

При планировании, создании, оформлении или структурировании уровней применять [.agents/skills/emergency-shift-level-authoring/SKILL.md](.agents/skills/emergency-shift-level-authoring/SKILL.md): осмысленные группы/зоны, повторяемые функциональные объекты и композиции в prefab, варианты/override с понятным владельцем. Подключение skill не означает, что старые сцены уже перегруппированы.

По поручению владельца от 2026-10-19 правила архитектуры SOD заменяют прежние противоречащие им архитектурные советы. Источник и границы переноса — [SOD adoption](Docs/Research/SOD_SKILLS_ADOPTION.md). Они не меняют принятый дизайн игры и не означают выполненную миграцию существующего кода. Инструкции человека и системные ограничения сохраняют свой приоритет.

## Качество кода

Целевая архитектура — MVC SOD: чистая C# Model, Controller/команды, View и отдельные Unity-адаптеры; внедрение зависимостей через Zenject/Extenject, без глобального mutable-состояния. Читаемость обязательна: одно действие на строке, явные блоки, без вложенных тернарных выражений. Баланс принадлежит неизменяемым SO-конфигам, runtime-состояние — экземпляру. Не разращивать выбор по видам врагов/оружия в общих потребителях. Подробности архитектуры — в SOD skill, сохранности ресурсов и сроков жизни — в unity-migration; реальные незакрытые замечания — Docs/ENGINEERING_REVIEW.md. Zenject и полная MVC-миграция ещё не внедрены.

## Неизменяемые без нового задания ограничения

- Строго сверху, 2D. Сцена/Canvas/расстановка редактируются в Unity; не регенерировать пользовательские карты.
- Сохранять ручные параметры/патрули/позиции и .meta GUID. Конфиги общие, runtime-состояние индивидуально.
- Агрессия после близости+видимости постоянна; нет потери цели/возврата домой. Световая реакция с задержкой, отход быстрее преследования. Лампы/выстрел не становятся защитным светом автоматически.
- Кровь один раз при смерти, процедурная; останки темнее/ниже живых, сохраняются. GoreProfile содержит варианты раскладки; новые нарисованные наборы — будущее.
- При оформлении комнат с монстрами оставлять осмысленные кровавые следы их жизнедеятельности: места кормления, волочение, небольшие останки. Использовать отдельные настраиваемые накладки, варьировать плотность и расположение по комнате; под фрагментами плоти кровь гуще. Это правило оформления, не автоматическая генерация крови у каждого врага.
- Принятые мембрана/реалистичные выстрелы/гильзы/foley не заменяются ранними бипами. Шаги игрока .24. Новое музыкальное направление сначала короткой пробой на оценку.
- OPT-01 массовой смерти отложен пользователем. Не строить большую систему пулов/ECS/менеджеров автоматически.
- Нет гарантии производительности по числу Update или одному прогону. Рабочие локальные чекпоинты есть; переходы кампании/динамические spawn ID ещё не готовы; второй вид доступен в тестовых сценах.

Объяснять владельцу, новичку C#, почему выбранные границы помогают следующему изменению. Проверять последствия изменения, обновлять профильную документацию. Действует прежнее поручение коммитить/пушить завершённую работу; чужие незавершённые правки сохранять отдельно.
