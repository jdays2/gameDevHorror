Эти правила действуют для этого Unity-проекта, не для других задач пользователя. Последние прямые указания пользователя имеют приоритет.

В начале **каждой задачи**, включая обсуждение/документацию, прочитать project skills:

4. [.agents/skills/sod-unity-architecture/SKILL.md](.agents/skills/sod-unity-architecture/SKILL.md) — принятая владельцем архитектура SOD; подробные references читать по задаче.

Чеклисты изменений/контента выполнять по применимости. Обсуждение само по себе не разрешает рефакторинг. Канонические skills хранятся здесь; копии установлены в ~/.codex/skills. После обновления синхронизировать копии. Не обещать автоматическое срабатывание skills вне области проекта.

Пять перенесённых из SOD skills находятся в `.agents/skills/`: `unity-pipeline`, `unity-package-management`, `ui`, `ui-ugui`, `physics-3d-collision`. Применять их по назначению; 3D PhysX не заменяет диагностику нашей Physics2D. Unity-команды выполнять с явным путём проекта и `--caller plugin --skill <имя>`.

При планировании, создании, оформлении или структурировании уровней применять [.agents/skills/emergency-shift-level-authoring/SKILL.md](.agents/skills/emergency-shift-level-authoring/SKILL.md): осмысленные группы/зоны, повторяемые функциональные объекты и композиции в prefab, варианты/override с понятным владельцем. Подключение skill не означает, что старые сцены уже перегруппированы.

По поручению владельца от 2026-10-19 правила архитектуры SOD заменяют прежние противоречащие им архитектурные советы. Источник и границы переноса — [SOD adoption](Docs/Research/SOD_SKILLS_ADOPTION.md). Они не меняют принятый дизайн игры и не означают выполненную миграцию существующего кода. Инструкции человека и системные ограничения сохраняют свой приоритет.

## Запуск текущей сцены · последнее решение владельца

Владелец отменил обязательный вход через MainMenu: BUG-048 — Won't do, вернуться к интеграции при подготовке рабочего билда. Это заменяет прежнее поручение об универсальной точке входа. Обычный Play запускается из открытой карты, `EditorSceneManager.playModeStartScene=null`. Другие чаты работают/проверяют текущие сцены напрямую; каталог меню больше не обязателен.

Не восстанавливать autoentry policy/автосинхронизацию каталога и Build Settings без нового поручения. Не оставлять MainMenu второй открытой сценой поверх уровня и не размещать её Canvas внутри карты. Сохранять рабочую карту и ручные изменения после Stop. Подготовленные сцена/ассеты/концепты/музыка меню и его runtime-переходы сохранены как отложенная работа. Контракт и причина отката — [MainMenu](Docs/Features/MainMenu.md).

## Качество кода

Целевая архитектура — MVC SOD: чистая C# Model, Controller/команды, View и отдельные Unity-адаптеры; внедрение зависимостей через Zenject/Extenject, без глобального mutable-состояния. Читаемость обязательна: одно действие на строке, явные блоки, без вложенных тернарных выражений. Баланс принадлежит неизменяемым SO-конфигам, runtime-состояние — экземпляру. Не разращивать выбор по видам врагов/оружия в общих потребителях. Подробности архитектуры — в SOD skill, сохранности ресурсов и сроков жизни — в unity-migration; реальные незакрытые замечания — база задач/багов Notion, адреса в Docs/NOTION_WORKFLOW.md. Extenject установлен; технический SOD-перенос текущих игровых границ подтверждён [FinalVerification44](Docs/Reports/FinalVerification44.md). Реальные Model/commands/controller и world/level/player scopes описаны в Features. Авторская приёмка остаётся отдельной карточкой Notion; будущие фичи, арт BUG-006/007 и незавершённое меню паузы не объявляются опубликованными этим результатом.

## Источники истины

[Docs/README.md](Docs/README.md) — индекс. [Notion](https://app.notion.com/p/3ff8d6dc06b6819caa69ece0495375a3) — основной источник всех планов, задач, багов, открытых вопросов и ченджлога/релизов. Обязательный протокол — [Docs/NOTION_WORKFLOW.md](Docs/NOTION_WORKFLOW.md), точные ID — [.agents/notion-project.json](.agents/notion-project.json). SPEC — локальные требования; ARCHITECTURE/Features — фактические технические контракты; Conventions — соглашения; Decisions — причины; Reports/Validation/Archive — свидетельства и история. Enemies/STALKER — игровой эталон, Guides — помощь владельцу, Concepts — происхождение материалов.

Перед каждой проектной задачей перечитать главную Notion, текущий план и затронутые карточки/баги; затем связанную локальную спеку. При сообщённом/обнаруженном дефекте без отдельного напоминания найти дубликат или создать BUG в Notion; в начале исправления обновить статус, после проверки записать результат/коммит и ченджлог. Непроверенное не отмечать исправленным, авторскую приёмку не отмечать за владельца. Перед записью перечитать изменяемую карточку. При сбое Notion явно сообщить несинхронизированную часть; не вести конкурирующий локальный план. Локальные дубли планов/реестров удалены после переноса в Notion; прежние редакции доступны в Git. [Рабочий паттерн](Docs/Guidelines/DOCUMENTATION.md) и [подбор skills](Docs/Roadmap/Skills.md) сохраняются. Полный проход собственного кода остаётся поручен владельцем: [этап 00](https://app.notion.com/p/3ff8d6dc06b681b6950bd8115222669c?pvs=204).

Каждой новой задаче присваивать постоянный уникальный номер `TASK-NNN` в поле «Код» Notion и в начале названия; владельцу всегда возвращать номер с кратким названием. Новые баги сохраняют `BUG-NNN`. Перед созданием сверять занятые номера, при обращении по номеру находить и перечитывать карточку. Полный порядок — раздел «Номера новых задач» в Docs/NOTION_WORKFLOW.md. Старые коды не перенумеровывать без поручения.

## Неизменяемые без нового задания ограничения

- Строго сверху, 2D. Сцена/Canvas/расстановка редактируются в Unity; не регенерировать пользовательские карты.
- Сохранять ручные параметры/патрули/позиции и .meta GUID. Конфиги общие, runtime-состояние индивидуально.
- Агрессия после близости+видимости постоянна; нет потери цели/возврата домой. Световая реакция с задержкой, отход быстрее преследования. Лампы/выстрел не становятся защитным светом автоматически.
- Кровь один раз при смерти, процедурная; останки темнее/ниже живых, сохраняются. GoreProfile содержит варианты раскладки; новые нарисованные наборы — будущее.
- При оформлении комнат с монстрами оставлять осмысленные кровавые следы их жизнедеятельности: места кормления, волочение, небольшие останки. Использовать отдельные настраиваемые накладки, варьировать плотность и расположение по комнате; под фрагментами плоти кровь гуще. Это правило оформления, не автоматическая генерация крови у каждого врага.
- Принятые мембрана/реалистичные выстрелы/гильзы/foley не заменяются ранними бипами. Шаги игрока .24. Новое музыкальное направление сначала короткой пробой на оценку.
- OPT-01 массовой смерти отложен пользователем. Не строить большую систему пулов/ECS/менеджеров автоматически.
- Нет гарантии производительности по числу Update или одному прогону. Рабочие локальные чекпоинты есть; переходы кампании/динамические spawn ID ещё не готовы; второй вид доступен в тестовых сценах.

Объяснять владельцу, новичку C#, почему выбранные границы помогают следующему изменению. Проверять последствия изменения, обновлять профильную документацию. Действует прежнее поручение коммитить/пушить завершённую работу; чужие незавершённые правки сохранять отдельно.
