# Уровни, враги, останки и группы

Применять при проектировании соответствующей системы. Ниже границы будущих решений, а не утверждение, что кампания, сохранение и пул уже существуют. OPT-01 остаётся отложенным; новые требования учитывать без автоматической реализации инфраструктуры.

## Данные и срок жизни

| Сущность | Содержимое | Владелец/срок |
|---|---|---|
| Level definition/catalog | ID, ссылка на сцену, вход/выход, описание целей/encounters | Контент проекта |
| Enemy definition/prefab | Общие характеристики, комплект компонентов/представления | Контент проекта |
| Spawn/encounter placement | ID экземпляра, профиль, позиция, маршрут, режим ожидания | Авторинг уровня |
| Живой actor | HP, агрессия, путь, атака, ссылки на цель | Текущий экземпляр |
| Короткий VFX | Всплеск, вспышка, движение разрыва | Ограниченное время эффекта |
| Remains record/visual | Вид разрушения, seed/результат, части/лужа, расположение | Состояние уровня после смерти |
| Save DTO | Версия схемы, ID уровня/объектов, выбранное сохраняемое состояние | Данные на диске, не MonoBehaviour |

Геометрия, двери и интерьер остаются в .unity/prefab, как выбрал пользователь. Каталог описывает переходы/контент, а не вводит второй генератор всей карты из координат JSON.

## Смерть и передача останков

Смерть подтверждает один владелец здоровья. В этот момент прекращаются урон, движение, обнаружение и участие в живой группе. Бой не ждёт окончания VFX или свободного слота пула. Один death event создаёт одну запись смерти/генерацию крови; повторная пуля/вызов не добавляет её снова.

Кровь/куски после передачи принадлежат уровню, не жизненному циклу повторно используемого живого actor. Его выключение/возврат не удаляет следы и не перемещает их к следующему spawn. Куски после оседания не должны сохранять AI/поиск пути/логику укуса. Сохранить принятые сортировку и затемнение останков.

Варианты смерти — несколько осмысленных наборов/поз с настраиваемым выбором, плюс процедурная вариативность; не только поворот одного спрайта. При необходимости воспроизведения хранить seed вместе с версией генератора/варианта либо итоговые трансформы/форму: один seed не гарантирует прежний результат после изменения алгоритма.

При additive-сценах создаваемые следы передавать явно уровню-источнику, не полагаться на случайную активную сцену. Политика сохранения на переходе/выгрузке задаётся уровнем/сессией. Не обещать бесконечное хранение всех туш на всех картах; удаление видимых останков или лимит должны быть согласованным игровым решением.

## Чекпоинты и сохранение — до реализации

Сначала определить таблицу правил: что сохраняется у игрока, у живых врагов, у дверей/лута, у волн и останков; что происходит после смерти/перезахода. Постоянная агрессия в текущем бою не определяет автоматически политику загрузки чекпоинта.

Нужны устойчивые ID уровня/размещённого объекта, а не имя, индекс поиска, GetInstanceID/GetEntityId или ссылка на объект в памяти. Для динамической волны определить воспроизводимую идентичность spawn. Проверять дубли ID после копирования объектов. ID типа контента и ID экземпляра различаются.

Save DTO хранит значения/ID, не ссылки на Rigidbody, coroutine, MonoBehaviour или asset как способ записи прогресса. Формат версионируется; изменение полей Unity и миграция сохранения — разные процессы. Восстановление происходит до включения обнаружения/атак; одна запись мёртвого врага не создаёт одновременно живой actor и его тушу. Обработать неизвестный ID/повреждённую версию явно.

## Группы и будущие орды

Encounter/wave отвечает за состав, условия активации, темп и учёт живых. Brain особи отвечает за её действие. Не добавлять знание каждой комнаты/волны в EnemyMotor или общий урон. Активация не сбрасывает уже начавшийся бой. Завершение уровня останавливает выдачу атак/спавнов, а не только прячет UI.

Проверять отдельно: спокойное движение10/20 особей, погоню у дверного проёма, одиночные смерти, одновременную гибель и накопление останков после нескольких боёв. Измерять время кадра/пики, GC Alloc, память, физику, рендер/свет и звук на целевой сборке. Одно среднее FPS не характеризует смерть группы.

Дорогие LOS/перестроения пути/создания VFX при необходимости распределять и бюджетировать, сохраняя приоритет опасных близких врагов. Не синхронизировать все случайные паузы и фазы анимации группы. Пространственный поиск/центральный tick/DOTS рассматривать только по измеренной проблеме, не по наличию отдельных Update.

При будущем пуле сбрасывать здоровье, агрессию, путь/цель, attack cooldown/одноразовые флаги, collider/rigidbody, визуал, звук и подписки. Старые корутины/отложенные укусы должны завершаться или проверять поколение аренды. Pool exhaustion имеет явную политику; допустимая деградация короткого эффекта не разрешает пропуск игрового урона/смерти или молчаливое удаление крови.

## Проверка жизненного цикла

Выбрать проверки по изменённой границе: две особи одного профиля независимы; повторная смерть не дублирует следы; перезапуск очищает transient-реестры; смена сцены не оставляет AudioListener/старую атаку; повторная аренда не унаследовала агрессию; сохранение/загрузка не воскресили убитого и не удвоили тушу. Не заявлять такие проверки пройденными, пока соответствующая система не реализована и не запущена.
