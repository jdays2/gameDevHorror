# Проверки проекта

Этот файл задаёт способ проверки, а не утверждает прохождение нового прогона. Результаты и их ревизии — [Reports/ValidationIndex](Reports/ValidationIndex.md).

## Выбор проверки

| Изменение | Проверка |
|---|---|
| Только документация | Ссылки/локальные пути, согласованность статусов, git diff --check |
| Model/команда/Controller | Компиляция и независимые EditMode на поведение, отказ, изоляцию экземпляров |
| Ввод/View/физический адаптер | Предыдущие проверки плюс запуск Play и консоль; ручную приёмку не отмечать за автора |
| Prefab/сцена/сериализация | GUID, обязательные ссылки, сохранность настроек; изменённые lifecycle/save-регрессии |
| DI/asmdef/runtime-интеграция | EditMode и целевая сборка; проверить исключение Editor/Development из release |

Игровые сценарии не симулировать автоматически лишь для повторения простого ручного прогона. Автоматизация оправдана сложным воспроизведением или прямым поручением. Переход в Play не доказывает баланс/внешний вид/FPS.

## Как повторить

В Unity: Window → General → Test Runner → EditMode → Run All. Тесты — `Assets/EmergencyShift/Tests/EditMode`.

В инструментированном development-player:

- `--sandbox-regression <absolute-report-json>` — маршрут песочницы.
- `--es-smoke-test --es-smoke-output <absolute-json-path>` — общие контракты.
- `--shotgun-regression <absolute-report-json>` — дробовик и оружейный payload.
- `--engineering-benchmark <absolute-report-json> <10|20>` — отдельный замер; не совмещать с другими тестами/сборками.

Обычный запуск не создаёт probes; в сохранённых сценах и release их быть не должно. Пользовательские checkpoint-слоты не использовать для тестов.

## Актуальные области

Область и дату прежнего прогона искать в [индексе свидетельств](Reports/ValidationIndex.md#актуальные-области). Они не подтверждают более поздний код автоматически.

## Сохранённые исторические измерения

[FirstShift, checkpoint и crowd-замеры](Reports/ValidationIndex.md#сохранённые-исторические-измерения) относятся к конкретным старым состояниям. JSON/скриншоты остаются в Docs/Validation; их пути не менялись. Новые отчёты должны указывать ревизию, сцену, метод, результат и ограничения.
