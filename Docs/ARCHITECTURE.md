# Архитектура

## Границы

Код разделён по назначению, настройки — по типу контента, сценические значения остаются на экземплярах. При переносе исходники/ресурсы перемещены с .meta, Unity GUID сохранены. Общее namespace EmergencyShift не мешает разделению файлов.

```text
Assets/EmergencyShift/
  Runtime/
    Core/Contracts/       урон, интеракции, защитный свет, факты для теней
    Definitions/          типы ScriptableObject
    Enemies/Common/      здоровье, восприятие, мотор, атака, патруль, навигация
    Enemies/Stalker/     решения вида, его анимация/звук/адаптеры
    Player/              ввод, движение, прицел, оружие, состояние игрока
    World/               свет, двери, лут, поверхности
    Combat/Weapons/      полёт/столкновение пули
    Levels/              контекст, цели и жизненный цикл уровня
    Persistence/         ID, снимки, файловый слот, адаптеры чекпоинтов
    Presentation/        эффекты и аудиорежиссёр
    UI/                  отображение существующего Canvas
    Development/         временные проверки, исключаемые из release
  Editor/                авторинг/инспекторы, отсутствуют в игроке
  Tests/EditMode/        независимые регрессии общих систем
  Data/                  Audio, Enemies, Weapons, Gore, Levels, Rendering
  Prefabs/               Player, Levels, Enemies, World, Loot, Combat
  Scenes/                FirstShift, BasementPrototype, LevelTemplate
  Art/ Audio/ Materials/ Shaders/
Concepts/Used/ Unused/    за пределами Assets, не импортируются
```

Сборки: Runtime, Development, Editor, EditModeTests. Runtime не зависит от Editor/Development. Development ограничена UNITY_EDITOR или UNITY_INCLUDE_INSTRUMENTATION; smoke запускается только в инструментированном development-игроке с явным аргументом. Служебные MonoBehaviour не перенесены в Editor-папку, где их временное добавление в Play могло бы сломаться.

## Сталкер и повторное использование

| Ответственность | Владелец |
|---|---|
| Текущее HP и однократная смерть | EnemyHealth2D |
| Видимость, радиус, воздействие света | EnemyPerception2D, контракт IThreatLight2D |
| Управление телом, обход, путь | EnemyMotor2D + EnemyChasePath2D |
| Соседи и бюджет поиска | CrowdAgent2D + NavigationWorkBudget2D |
| Тайминг выпада, дистанция/стена, доставка урона | EnemyMeleeAttack2D |
| Мирные точки/паузы | EnemyPatrol2D |
| Решение, какое состояние нужно этому виду | ShadowStalker2D, явная машина состояний |
| Кровь/разрыв по событию смерти | EnemyDeathEffects2D + GoreBurst2D |
| Попадание/тени | EnemyHitResponse2D; CreatureGroundShadow2D через EnemyPresentationSource2D |
| Кадры, мембрана, сигнал угрозы | Видовые Stalker* компоненты |

Это композиция: следующий AI получает нужные компоненты и собственные решения, не наследуется от Сталкера и не добавляет `if (enemyType==...)` в его код. Общие модули не содержат собственных Update: AI вызывает их в физическом шаге. События отделяют реакции представления от смерти/укуса. Видовая анимация и мембранные звуки намеренно не объявлены универсальными.

## Три вида данных

1. **Общие настройки:** EnemyDefinition (HP, преследование, укус), StalkerBehaviourProfile (страх/отход), EnemyPatrolProfile (скорость/паузы). Несколько врагов ссылаются на один asset. Для разновидности — Duplicate asset и новая ссылка.
2. **Расстановка:** позиция, Detection Radius, Attacks Enabled, Patrol Enabled, Use Patrol Area, Area Offset/Size, маска стен. Индивидуальные данные сцены, не общий SO.
3. **Runtime:** Current HP, Aggro, State, путь, цель патруля, таймеры, патроны, модули. Только экземпляр, никогда не запись в общий asset.

При миграции созданы пять assets: Stalker-Default, два light-профиля с задержкой .45/.33 и два patrol-профиля со скоростью .6/.65. Сохранены значения31 экземпляра, пользовательские правки не усреднены. Отсутствующий обязательный профиль — явная ошибка, а не скрытая подмена дефолтом.

Конфиги существовали раньше: WeaponDefinition, ShotVisualProfile, StalkerAudioSet, PlayerAudioSet, PlayerWorldAudioSet, DoorAudioSet, AudioMoodProfile. Проблемой было неполное покрытие; теперь баланс Сталкера тоже вынесен. Смена дальности фонаря сама по себе не требует нового класса: Flashlight2D остаётся конкретным источником с IThreatLight2D. Будущий флаер потребует другой реализации и выбора стимулов; сейчас его нет.

## Остальные связи

Пуля обращается к Damageable2D, поверхность определяет звук. Подборы используют IAutoPickup, двери IInteractable; DoorAccess2D добавляет необязательный замок. PlayerAccessCards2D — локальное множество, не глобальный инвентарь.

LevelContext2D связывает игрока/фонарь в пределах сцены, заполняет только отсутствующие ссылки. LevelRig — готовые игрок/камера/Canvas/контекст, LevelTemplate — редактируемая основа. Реестры фильтруются по сцене и очищаются при выгрузке. Геометрия/UI/враги авторятся в сцене, а не создаются bootstrap при каждом Play.

Отдельные Update/FixedUpdate у камер, аудио и визуальных компонентов нормальны. Централизация без измерений не нужна: бюджетируются дорогие операции, не само имя метода.

## Уровень и сохранение

- **LevelDefinition** описывает стабильный levelId, путь сцены, версию совместимости сохранения, карту выхода и приоритетные правила целей. **LevelCatalog** находит описание по ID. Он не создаёт комнаты. nextLevelId зарезервирован: автоматический переход кампании пока не подключён.
- **LevelObjectiveController2D** пересчитывает цели по событиям карт/владения оружием. Первый подходящий rule побеждает: карта выхода имеет приоритет над остальными условиями. Цели не сканируются каждый Update.
- **LevelCompletionView2D** отображает цель/результат на существующем Canvas. **LevelRunController2D** владеет завершением и временем попытки. **LevelParticipant2D** останавливает явно назначенную деятельность при выходе; сценарий уровня не импортирует конкретный вид врага.
- **PersistentEntity2D** хранит уникальный ID расставленного объекта. Его компоненты **ICheckpointParticipant** пишут отдельные versioned payload. Добавление нового вида требует его адаптера состояния, а не нового if в общем загрузчике.
- **LevelCheckpointController2D** снимает всю сцену по запросу volume, ждёт оседания частей/остановки дверей и пишет фактическое состояние живого игрока. **CheckpointStore** проверяет версию/ID и атомарно заменяет JSON через временный файл, сохраняя предыдущий .bak.

Сохраняются здоровье, позиция/направление/фонарь, карты, оружие и патроны, установленные модули; остаток в коробках/собранные предметы; двери/разблокировка; активированные группы; HP/агрессия/состояние/таймеры/маршрут Сталкеров; положение, цвет и форма осевшей крови/частей. Восстановление не вызывает Died и не генерирует разрыв повторно. Конфиги не сериализуются целиком: оружие восстанавливается через contentId/WeaponCatalog.

Перед изменением мира загрузчик проверяет соответствие levelId/saveRevision, полного набора ID и ключей компонентов. Неизвестная версия/изменённая структура отклоняются с уведомлением. Это не обещание автоматической миграции любых будущих форматов. [Политика и настройка](Guides/CHECKPOINTS.md).

## Останки и профили

**GoreProfile** хранит размер лужи, задержку, импульсы/высоту/гравитацию и варианты раскладки. StalkerRupture содержит radial, heavy-close, scattered: разные размерные диапазоны, распределение спрайтов и сила выброса, по8 частей. Это варианты на текущей библиотеке рисунков, не три новых нарисованных набора туш.

**GoreBurst2D** производит разрыв. **RemainsRecord2D** на независимом корне сцены владеет лужей/частями и их снимком. **RemainsPartIdentity2D** связывает осевший кусок с индексом исходного спрайта. Удаление живого actor не удаляет корень останков. Снимок снимается до удаления actor: отдельного каталога останков удалённых/pool-возвращённых actor ещё нет. Пул врагов в проекте не используется.

## Оставшиеся ограничения

StalkerAudio2D остаётся видовым адаптером. Баланс оружия теперь только в WeaponDefinition; ручные дублирующие damage/rate/range/ammo поля удалены после сравнения значений. ShotVisualProfile — отдельная настройка визуала, не второй источник урона.

Следующий вид ещё надо проверить реальным контентом. Нет полноценного инвентаря, автоматического переноса между уровнями, динамического спавнера с сохранением новых runtime-ID и пула actor. Сохранение поддерживает авторенные объекты данной сцены. Изменив контракт/библиотеку частей, увеличивайте saveRevision и явно начинайте новую попытку либо пишите мигратор.

Локальный путь/раздвигание не рассчитаны на тысячи агентов. Сравнительный native-замер10/20 выполнен; большой пул/ECS/DI/центральный Update не вводились. Постоянные следы не удаляются ради цифр. [Аудит](ENGINEERING_REVIEW.md), [границы измерений](OPTIMIZATION_BACKLOG.md).
