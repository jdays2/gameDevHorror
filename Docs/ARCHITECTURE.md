# Архитектура

## Границы

Основная сцена — [MechanicsSandbox](SANDBOX.md). FirstShift и его профиль удалены; Campaign.asset пока пуст. Системы целей/чекпоинтов сохранены, но в песочнице отсутствуют их контроллеры/слоты.

Код разделён по назначению, настройки — по типу контента, сценические значения остаются на экземплярах. При переносе исходники/ресурсы перемещены с .meta, Unity GUID сохранены. Общее namespace EmergencyShift не мешает разделению файлов.

```text
Assets/EmergencyShift/

    Definitions/          типы ScriptableObject
    Enemies/Common/      здоровье, восприятие, мотор, атака, патруль, навигация
    Enemies/Stalker/     решения вида, его звук/адаптеры
    Enemies/Sleeper/     сон/пробуждение/погоня/выпад, звук/адаптеры
    Player/              ввод, движение, прицел, оружие, состояние игрока
    World/               свет, двери, лут, поверхности
    Combat/Weapons/      пуля, инвентарь и индивидуальные циклы оружия
    Levels/              контекст, цели и жизненный цикл уровня
    Persistence/         ID, снимки, файловый слот, адаптеры чекпоинтов
    Presentation/        эффекты и аудиорежиссёр
    UI/                  отображение существующего Canvas
    Development/         временные проверки, исключаемые из release
    Sandbox/             управление тестом, временное HP, закреплённые цели
  Editor/                авторинг/инспекторы, отсутствуют в игроке
  Tests/EditMode/        независимые регрессии общих систем
  Data/                  Audio, Enemies, Weapons, Gore, Levels, Rendering

Development ограничена UNITY_EDITOR или UNITY_INCLUDE_INSTRUMENTATION; smoke запускается только в инструментированном development-игроке с явным аргументом. Служебные MonoBehaviour не перенесены в Editor-папку, где их временное добавление в Play могло бы сломаться.

## Сталкер и повторное использование

| Ответственность | Владелец |
|---|---|
| Текущее HP и однократная смерть | EnemyHealth2D |
| Видимость, радиус, воздействие света | EnemyPerception2D, контракт IThreatLight2D |
| Управление телом, обход, путь | EnemyMotor2D + EnemyChasePath2D |
| Соседи и бюджет поиска | CrowdAgent2D + NavigationWorkBudget2D |
| Тайминг выпада, дистанция/стена, доставка урона | EnemyMeleeAttack2D |
| Мирные точки/паузы | EnemyPatrol2D |
| Решение, какое состояние нужно этому виду | ShadowStalker2D и Sleeper2D, отдельные машины состояний |
| Кровь/разрыв по событию смерти | EnemyDeathEffects2D + GoreBurst2D |
| Попадание/тени | EnemyHitResponse2D; CreatureGroundShadow2D через EnemyPresentationSource2D |
| Кадры | CreatureSpriteAnimator2D через EnemyPresentationSource2D; совместимая оболочка StalkerSpriteAnimator |
| Голос/контакты и сигнал угрозы | StalkerAudio2D / SleeperAudio2D и их AudioThreat-адаптеры |

Это композиция: следующий AI получает нужные компоненты и собственные решения, не наследуется от Сталкера и не добавляет `if (enemyType==...)` в его код. Общие модули не содержат собственных Update: AI вызывает их в физическом шаге. События отделяют реакции представления от смерти/укуса. Общий проигрыватель кадров извлечён при подключении второго вида, использующего тот же набор анатомии; звук и решения остаются видовыми. Для Спящего общая атака поддерживает фиксированное направление без обходного поворота, прежний режим Сталкера сохранён.

## Три вида данных

1. **Общие настройки:** EnemyDefinition (HP, преследование, укус), StalkerBehaviourProfile (страх/отход), EnemyPatrolProfile (скорость/паузы). Несколько врагов ссылаются на один asset. Для разновидности — Duplicate asset и новая ссылка.
2. **Расстановка:** позиция, Detection Radius, Attacks Enabled, Patrol Enabled, Use Patrol Area, Area Offset/Size, маска стен. Индивидуальные данные сцены, не общий SO.
3. **Runtime:** Current HP, Aggro, State, путь, цель патруля, таймеры, патроны, модули. Только экземпляр, никогда не запись в общий asset.

При миграции созданы пять assets: Stalker-Default, два light-профиля с задержкой .45/.33 и два patrol-профиля со скоростью .6/.65. Сохранены значения31 экземпляра, пользовательские правки не усреднены. Отсутствующий обязательный профиль — явная ошибка, а не скрытая подмена дефолтом.

Конфиги существовали раньше: WeaponDefinition, ShotVisualProfile, StalkerAudioSet, PlayerAudioSet, PlayerWorldAudioSet, DoorAudioSet, AudioMoodProfile. Проблемой было неполное покрытие; теперь баланс Сталкера тоже вынесен. Смена дальности фонаря сама по себе не требует нового класса: Flashlight2D остаётся конкретным источником с IThreatLight2D. Будущий флаер потребует другой реализации и выбора стимулов; сейчас его нет.

Общий `EnemyDeathAudioSet` хранит три клипа разрыва. Видовые аудиоадаптеры выбирают их через `EnemyDeathAudioVariants` и играют на своих существующих источниках. Последний выбор хранится в runtime-кэше по набору на время Play, общий asset не меняется. У общего выбора нет знаний о brain/виде/состояниях врага. Новый числовой вариант смерти добавляется в набор; оружие, камера, урон и HUD не меняются.

## Остальные связи

`BloodPoolProfile` хранит три подготовленные процедурные формы, stable ID и параметры короткой анимации. `BloodPool2D` выбирает форму и раскладку на смерть; после оседания Update выключен. RemainsRecord остаётся владельцем лужи на уровне. Снимок хранит bloodVariantId плюс прежние трансформы/цвет/видимость; сначала восстанавливаются спрайты, затем осевшее состояние. Старые записи без ID используют прежние круговые спрайты. Порядок 21 renderer slot сохранён. Выбор не зависит от вида brain; новая форма добавляется данными профиля.

Пуля обращается к Damageable2D, поверхность определяет звук. Подборы используют IAutoPickup, двери IInteractable; DoorAccess2D добавляет необязательный замок. PlayerAccessCards2D — локальное множество, не глобальный инвентарь.

LevelContext2D связывает игрока/фонарь в пределах сцены, заполняет только отсутствующие ссылки. LevelRig — готовые игрок/камера/Canvas/контекст, LevelTemplate — редактируемая основа. Реестры фильтруются по сцене и очищаются при выгрузке. Геометрия/UI/враги авторятся в сцене, а не создаются bootstrap при каждом Play.

LocalLampAudioSet хранит клипы, громкость и дистанции слышимости. LocalLampAudio2D читает фактическую яркость Light2D после Update света; предыдущая яркость, выбранный контакт, cooldown и два голоса принадлежат экземпляру. Отдельного аудиотаймера мерцания нет. Явный игрок/LevelContext задаёт слушателя в XY; стены глушат звук, OnDisable останавливает голоса. Новый оттенок/радиус или аудионабор не требует изменений AI, камеры и оружия. Больничные трубки имеют LocalLampConfiguration2D с inline LocalLampSceneSettings: цвет, радиус/яркость света, радиус/громкости звука, фаза/мерцание и длина корпуса принадлежат каждому экземпляру сцены. Config применяет значения без собственного Update; Fixture меняет масштаб отдельно от корня света/аудио и сохраняет заднюю кромку у стены. Для этих ламп Settings имеют приоритет над LocalLightProfile и legacy-полями; остальные светильники сохраняют старую схему. Общие SO не мутируют. Подключены шесть ламп MechanicsSandbox и семь BasementPrototype; [авторинг](Guides/HOSPITAL_LAMPS.md).

CeilingLightOcclusion2D на семи лампах BasementPrototype моделирует свет над низкой мебелью. Сценовый массив fullHeightBlockers содержит прямоугольные высокие стены и створку двери. Компонент создаёт и освобождает индивидуальную временную cookie-маску, пересчитывая её при изменении геометрии или радиуса. Маска заменяет плоские тени только этих ламп; LocalLamp2D продолжает владеть яркостью/цветом/мерцанием, а фонарь — собственными тенями от мебели. Позиции ламп и столов не меняются, состояния AI и shared SO не затрагиваются. Это упрощение для 2D: конечные короткие тени по физической высоте мебели не рассчитываются.

Отдельные Update/FixedUpdate у камер, аудио и визуальных компонентов нормальны. Централизация без измерений не нужна: бюджетируются дорогие операции, не само имя метода.

## Уровень и сохранение

- **LevelDefinition** описывает стабильный levelId, путь сцены, версию совместимости сохранения, карту выхода и приоритетные правила целей. **LevelCatalog** находит описание по ID. Он не создаёт комнаты. nextLevelId зарезервирован: автоматический переход кампании пока не подключён.
- **LevelObjectiveController2D** пересчитывает цели по событиям карт/владения оружием. Первый подходящий rule побеждает: карта выхода имеет приоритет над остальными условиями. Цели не сканируются каждый Update.
- **LevelCompletionView2D** отображает цель/результат на существующем Canvas. **LevelRunController2D** владеет завершением и временем попытки. **LevelParticipant2D** останавливает явно назначенную деятельность при выходе; сценарий уровня не импортирует конкретный вид врага.
- **PersistentEntity2D** хранит уникальный ID расставленного объекта. Его компоненты **ICheckpointParticipant** пишут отдельные versioned payload. Добавление нового вида требует его адаптера состояния, а не нового if в общем загрузчике.
- **LevelCheckpointController2D** снимает всю сцену по запросу volume, ждёт оседания частей/остановки дверей и пишет фактическое состояние живого игрока. **CheckpointStore** проверяет версию/ID и атомарно заменяет JSON через временный файл, сохраняя предыдущий .bak.

Сохраняются здоровье, позиция/направление/фонарь, карты, оружие и патроны, установленные модули; остаток в коробках/собранные предметы; двери/разблокировка; активированные группы; HP/агрессия/состояние/таймеры/маршрут Сталкеров; положение, цвет и форма осевшей крови/частей. Восстановление не вызывает Died и не генерирует разрыв повторно. Конфиги не сериализуются целиком: оружие восстанавливается через contentId/WeaponCatalog.

Перед изменением мира загрузчик проверяет соответствие levelId/saveRevision, полного набора ID и ключей компонентов. Неизвестная версия/изменённая структура отклоняются с уведомлением. Это не обещание автоматической миграции любых будущих форматов. [Политика и настройка](Guides/CHECKPOINTS.md).

## Останки и профили

**GoreProfile** хранит размер лужи, задержку, импульсы/высоту/гравитацию и варианты раскладки. `StalkerRupture` содержит три прежних ID с исходным телом и 11 фрагментами (восемь старых плюс три куска плоти), а также три новых состава hollow-core/retained-core/split-core из 13/14/16 частей. Старые сохранённые составы из восьми частей остаются допустимы: исходные ID не скрывают прежнее тело.

Оба профиля используют необязательные `GoreVariant.pieces`: конкретные индексы рисунков, начальные смещения, масштаб и множители импульса/подлёта. `SleeperRupture` содержит три состава 13/14/16 частей с разными корпусами и наличием отдельного глаза. Четыре формы плоти общие, спрайты имеют палитру соответствующего вида; renderer/оружие не проверяют вид. `replaceOriginalBody` скрывает прежний death-body после выпуска частей; его тень следует видимости body. Старые индексы фрагментов и ID вариантов сохранены, snapshot хранит фактический результат без повторной генерации. Лужи BloodPool используют sorting order −1, ниже останков (0) и выше пола (−10).

**GoreBurst2D** производит разрыв. **RemainsRecord2D** на независимом корне сцены владеет лужей/частями и их снимком. **RemainsPartIdentity2D** связывает осевший кусок с индексом исходного спрайта. Удаление живого actor не удаляет корень останков. Снимок снимается до удаления actor: отдельного каталога останков удалённых/pool-возвращённых actor ещё нет. Пул врагов в проекте не используется.

## Песочница

`SandboxSession2D` владеет R/T в этой сцене. `SandboxAmmoSupply2D` — многоразовый ящик тира за общим `IInteractable`: E вызывает обычный `PlayerWeapon2D.AddAmmo` для выбранного оружия, сохраняя лимит запаса и отдельную перезарядку. Ящик не хранит расходуемый остаток и не проверяет конкретный тип оружия; дальность задана на экземпляре сцены, боезапас принадлежит инвентарю игрока. `SandboxHealthZone2D` хранит предыдущие HP/предел только на время нахождения игрока в тире и меняет экземпляр через `PlayerLife2D.SetHealthCapacity`; выход не лечит игрока снаружи и не воскрешает погибшего. `SandboxStationaryStalker2D` закрепляет тело и запрещает укусы; настоящие здоровье/реакции/смерть остаются у прежних компонентов. Разные HP мишеней — три EnemyDefinition, не новые ветки в пуле/HUD. Одноразовый Editor-авторинг сохраняет обычную .unity; при Play комнаты не генерируются.

## Оставшиеся ограничения

StalkerAudio2D остаётся видовым адаптером. Баланс оружия теперь только в WeaponDefinition; ручные дублирующие damage/rate/range/ammo поля удалены после сравнения значений. ShotVisualProfile задаёт вспышку/попадание и ссылается на ProjectileVisualProfile для полёта. Пистолет и дробовик разделяют CommonProjectile, не второй источник урона.

Следующий вид ещё надо проверить реальным контентом. Есть небольшой инвентарь оружия; нет общего инвентаря предметов, автоматического переноса между уровнями, динамического спавнера с сохранением новых runtime-ID и пула actor. Сохранение поддерживает авторенные объекты данной сцены. Изменив контракт/библиотеку частей, увеличивайте saveRevision и явно начинайте новую попытку либо пишите мигратор.

Локальный путь/раздвигание не рассчитаны на тысячи агентов. Сравнительный native-замер10/20 выполнен; большой пул/ECS/DI/центральный Update не вводились. Постоянные следы не удаляются ради цифр. [Аудит](ENGINEERING_REVIEW.md), [границы измерений](OPTIMIZATION_BACKLOG.md).

## Оружие: данные, наследование и композиция

`WeaponDefinition` хранит общие числа и создаёт обычный `WeaponCycle`. Текущий пистолет использует `MagazineWeaponDefinition` и `MagazineWeaponCycle` для атомарной замены магазина. `PumpShotgunCycle` теперь наследует общие loaded/reserve/отмену/снимок от MagazineWeaponCycle, добавляя собственную помпу и поштучный Tick. `PumpShotgunDefinition` наследует описание и переопределяет веер/фабрику цикла, `PumpShotgunCycle` расширяет общий расход патрона/cooldown помпой и поштучной зарядкой. Это две реальные вариации алгоритма. Новая числовая разновидность пистолета обходится новым asset; другой цикл потребует собственной реализации за тем же контрактом.

`WeaponInventory` инкапсулирует словарь владения: свой cycle на каждый contentId, уникальный selectionSlot, независимые патроны и проверка снимка до изменения. Магазин включён в TotalAmmo, Reserve вычисляется как TotalAmmo − Loaded; вставка перемещает патрон, а не создаёт его. Общие ScriptableObject не изменяются во время игры.

`PlayerWeapon2D` связывает ввод/прицел с активным cycle и единым созданием projectile/effects. HUD читает свойства, не проверяет класс оружия. `BulletProjectile2D` использует Damageable2D без знания Сталкера. WeaponAudioProfile задаёт вариации и вид гильзы; отсутствие профиля сохраняет принятую библиотеку пистолета. ShotFired/Operation/CasingEjected разделяют выстрел, помпу, вставку и выброс. Аудио переиспользует существующие ограниченные голоса; одна громкая реакция на материал за залп, hit-cue Сталкера не чаще 0.05 с. Гильза хранит профиль выстрелившего оружия до приземления, даже после смены оружия.

PlayerCheckpoint2D пишет format2 с явным hasInventory, всеми contentId, патронами, фазами и оставшимися таймерами; ключ player.v1 сохранён. Старый format1 пистолета переносится в магазин min(capacity,total), остаток в резерв. Внутренний цикл пистолета format2 хранит также незавершённую замену магазина. Цикл дробовика сохранил format1 и совместимость. Летящие пули, гильзы и звук не сохраняются. Снимок не требует новых веток в общем файловом загрузчике.

## Пробный диалог

DialogueSequence хранит общие данные говорящих, реплик и ответов со стабильными ID. `entryId`, `nextId` и `choices[].targetId` задают граф; порядок массива не задаёт маршрут. Валидация до захвата контекста отвергает отсутствующие/повторные ID, неверные цели и одновременные next/choices. DialogueRun — отдельное прохождение без зависимости от ввода, UI, оружия или событий мира; выбор обязателен на развилке, пустой next завершает разговор. Несколько прохождений не делят позицию и не пишут в asset. DialogueStyle содержит оформление/размеры. DialogueView показывает один портрет, текст, плавную тень и переиспользуемые кнопки из сохранённого шаблона; кнопки создаются по потребности, ограничение в два ответа отсутствует. DialogueInteraction2D использует IInteractable/E. DialogueSession соединяет ввод, прохождение и отображение, владеет прежней видимостью Canvas/прицела/курсора. OnDisable/Cancel освобождают контекст.

GameplayInputBlock выдаёт владельцу IDisposable-захват. Игровой ввод мотора/оружия/фонаря/взаимодействия и R/T песочницы проверяет этот захват; он действует глобально, как Time.timeScale, и не содержит ссылки на скрытого глобального игрока. Оружие остаётся enabled: состояние цикла не сбрасывается через OnDisable. После последней реплики захват снимается только после отпускания E/Space/Enter/ЛКМ и отдельного кадра, чтобы подтверждение не стало выстрелом. Сеанс восстанавливает исходный timeScale, в том числе отличный от 1, и исходную видимость HUD. Вызовы Acquire/Dispose разных владельцев не разблокируют друг друга.

WorldMotionPause выдаёт отдельную IDisposable-аренду остановки масштабируемого мира, восстанавливает прежний timeScale после последнего владельца. LevelAudioDirector2D различает эту остановку и обычную паузу: диалог из идущего мира сохраняет проигрывание аудиослоёв, прежняя пауза/AudioListener.pause остаётся паузой. Прицел не читает мышь под захватом, камера не сглаживает при нулевом deltaTime. Фоновый звук не останавливается и не приглушается самим диалогом.

`DialogueSession.Transitioned` выдаёт неизменяемое уведомление DialogueTransition: общий asset, Started/Advanced/ChoiceSelected/Completed/Cancelled, ID исходной/целевой реплики и ответа. Будущий адаптер событий сможет подписаться на время жизни сеанса и сопоставлять эти ID с последствиями, не добавляя обязанности к UI/оружию/AI. Сейчас подписчика с игровыми эффектами нет. Условия доступности, проверка/выполнение эффектов, однократность, транзакции, сохранение и восстановление прогресса требуют отдельного проектирования; уведомление само их не решает. Стабильные ID контента после подключения событий нельзя произвольно менять.

`Prefabs/UI/DialogueUI.prefab` объединяет DialogueSession и Canvas/DialogueView с внутренними ссылками, общим стилем и шаблоном ответа. HUD/прицел принадлежат сцене и назначаются overrides экземпляра; prefab не содержит тестового разговора, маркера или EventSystem. Runtime по-прежнему получает явные ссылки, без глобального поиска игрока и без DontDestroyOnLoad.

DialoguePrefabAuthoring экспортирует существующий UI через Preview Scene и связывает исходную группу с prefab через ConvertToPrefabInstance, сохраняя объекты/ссылки и сценовые добавления. Установка в другую сцену назначает её HUD/прицел, переиспользует один совместимый EventSystem или создаёт его при отсутствии; второй сеанс в той же сцене отвергается, включая неактивный. Команда не сохраняет остальные ручные изменения автоматически. Общая компоновка редактируется в Prefab Mode; инструкция — в [дизайн-системе](UI/DIALOGUE_DESIGN_SYSTEM.md#подключение-prefab-в-другой-сцене).

DialogueSandboxAuthoring использует этот prefab при добавлении новой пробы, не строит отдельную копию диалогового Canvas и не перестраивает карту. Проба содержит две ветки с общим финалом, без checkpoint/кампании, меню и игровых последствий. Извлечение prefab не меняет прежние уведомления о переходах и не добавляет работу с сохранениями.

## Контуры теней окружения

IndustrialProps02 использует стандартный URP ShadowCaster2D с источником SpriteRenderer, Cast Shadow и alphaCutoff .2. Provider берёт треугольную сетку спрайта: FullRect давал прямоугольную тень прозрачного холста. Editor-авторинг EnvironmentReviewBuilder запекает Tight-контур PNG с порогом .2 и детализацией .05, с отверстиями. Это также исключает почти прозрачные фрагменты по краям. Контур сохранён в .meta, runtime не анализирует пиксели. Вызов внутреннего SpriteUtility GenerateOutlineFromSprite изолирован в авторинге и явно проверяет совместимость версии Unity.

Длину и направление считает URP для каждого Light2D. Временные PropGroundShadow2D, PropShadowProfile и LowPropShadows удалены. Коллайдеры движения/лучей остаются простыми и независимыми от визуального контура. Камера, защитные свойства света, AI, тени Сталкера/игрока и их общий материал не меняются. Это стандартные 2D-тени, без физической модели высоты предмета.

## Игровой HUD

GameplayHudView — представление под существующим Canvas. Читает PlayerLife2D (HealthChanged / отдельное Damaged только для принятого урона), PlayerWeapon2D, Flashlight2D и необязательный PlayerAccessCards2D. HudWeaponRow показывает WeaponDefinition и переставляется между двумя редактируемыми anchors; правила владения/выбора остаются у оружия. GameplayHudStyle содержит цвета, длительности и необязательные hit clips; таймеры и потерянный участок HP принадлежат экземпляру. Отключение Canvas удаляет подписки/отклик; включение заново читает состояние. Старый PrototypeHud сохраняет контекст, подборы и поражение. [Настройка](UI/HUD_DESIGN_SYSTEM.md).
