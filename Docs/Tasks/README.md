## Как ведём план

1. В начале каждой задачи агент читает план и связанную карточку, сопоставляет поручение с существующим пунктом. Для новой многошаговой работы создаёт устойчивый ID и карточку; небольшой правке достаточно пункта со ссылкой на профильный документ.
2. До реализации фиксирует результат, объём и проверяемые критерии. Прямое поручение может менять очередь; будущая идея не становится текущей работой только из-за наличия в плане.
3. По мере проверенного выполнения ставит `[x]` у шагов. Частичный шаг оставляет `[ ]` с пояснением. При расширении объёма обновляет критерии.
4. Закрывает общий пункт, когда выполнены его критерии, и указывает подтверждение в карточке: файл, отчёт, проверку или явное решение владельца. Техническая готовность и художественное одобрение учитываются отдельно.
5. Перед итоговым ответом сверяет карточку, план, таблицу статусов здесь и профильные требования. Оставшееся записывает открытым. Чужие незавершённые задачи не объявляет проверенными.

Отметки обновляет агент при выполнении поручения; это не фоновый мониторинг. Markdown хранит переносимые чекбоксы; возможность переключать их мышью зависит от просмотрщика.

Полные требования остаются в профильных документах. Карточка управляет работой и не дублирует спецификацию.
