# Адаптивный звук: первый игровой срез

15 октября2026. Пробная интеграция по прямому поручению пользователя. Три фактуры из StatePreviewV2 оставлены для проверки в игре; это не финальное художественное утверждение. Существующие пистолет, гильзы, мембрана сталкера, дверь и подбор сохранены.

## Что попробовать

1. Открой BasementPrototype и запусти Play. Постой, затем пройдись: тихий фон и шаги.
2. Посвети на сталкера или прислушайся к его реальному звуку. Постепенно добавится слой угрозы. Скрытый бесшумный враг за стеной музыку не включает.
3. Подпусти замеченного преследователя ближе2.5 единиц, встреть двух замеченных преследователей либо выстрели по уже обнаруженной угрозе. Добавится более плотная фактура боя, даже до укуса.
4. Отойди/погаси свет/уничтожь врага. После удержания состояния дополнительные слои плавно уйдут. Агрессия AI этим не сбрасывается.
5. Нажми F: механический щелчок. После расхода патронов нажатие ЛКМ даёт пустой спуск.
6. Стреляй в бетон/деревянные объекты: звук попадания зависит от ImpactSurface2D. У сталкера остаются его собственные ранения без двойного мясного импакта.

## Где настраивать в Unity

| Место | За что отвечает |
|---|---|
| Сцена → LevelAudio → LevelAudioDirector2D | Ссылки, локальный Volume; в Play ниже видны Mood, воспринимаемые/агрессивные враги, уровни трёх слоёв и duck |
| Assets/EmergencyShift/Settings/SurvivalAudio.asset | Общий профиль громкости и переходов |
| Assets/EmergencyShift/Audio/Atmosphere | Три9-секундные PCM-петли ExploreLoop/ThreatLoop/CombatLoop |
| Player → PlayerFootsteps2D | Distance Per Step=1.05, Minimum Interval=.22, Pitch Variation=.025 |
| Assets/EmergencyShift/Audio/PlayerWorld/PlayerWorldAudio.asset | Шаги Concrete/Wood/Tile, щелчок фонаря, пустой спуск и их уровни |
| Player → World audio | Два сохранённых канала шагов и один utility |
| Player → PlayerAudio2D | Существующие пистолет/гильзы/подбор, теперь включённые материальные импакты |
| Assets/EmergencyShift/Audio/PistolIndoor/PistolIndoorAudio.asset | Сохранённые выстрелы/гильзы плюс новые Concrete/Wood и повторно использованные принятые Flesh Hit |

Volume на дочерних AudioSource фоновых петель каждый кадр задаёт контроллер. Для изменения уровня пользуйся Volume контроллера или профилем. Checkbox контроллера полностью останавливает только фон; остальные звуки продолжают работать.

Профиль — общий ScriptableObject-ассет. Его изменения в Inspector могут сохраниться даже при редактировании в Play. Для отдельного уровня создай дубликат профиля и назначь его соответствующему LevelAudioDirector2D. Компонентный Volume — локальное значение конкретного экземпляра.

### Начальные значения профиля

| Поле | Значение | Практический смысл |
|---|---|---|
| Master Volume |.7 | Общая громкость фактур; умножается на локальный Volume |
| Exploration / Threat / Combat Gain |.6/.85/.9 | Уровень каждого слоя при его активности |
| Rise / Fall Seconds |.45/3.5 | Характерное время экспоненциального сглаживания; примерно1с до90% нового уровня, спад медленнее |
| Threat / Combat Hold Seconds |5/3 | Удержание состояния после последнего сигнала |
| Perception Memory Seconds |1.25 | Краткая память уже замеченного источника при повороте/скрытии |
| Awareness Distance |9 | Максимальная дальность источников для музыкальной оценки |
| Close Combat Distance / Crowd Enemies For Combat |2.5/2 | Один замеченный преследователь вблизи либо двое в пределах Awareness Distance включают бой без выстрела |
| Observation Interval |.12 | Частота проверки небольшого списка источников |
| Duck Gain |.75 | Ослабление только фона на важном сигнале; фактура остаётся различимой |
| Shot / Cue Duck Seconds |.22/.4 | Удержание duck после выстрела/важного сигнала сталкера |
| Low Health Gain |.9 | Дополнительное ослабление фона при неполном здоровье; без сердцебиения/псевдоконтузии |

## Как определяется состояние

Враг учитывается только в своей сцене и только если он жив. Реестры очищаются при отключении/выгрузке; поиска всей сцены каждый кадр нет.

Зрительное обнаружение: точка тела внутри экрана, основной луч Flashlight2D.Illuminates либо локальная лампа, плюс проверка стен/закрытой двери. Освещённость слабой лампой не меняет страх сталкера: его AI по-прежнему реагирует на фонарь. Через стену от игрока лампа не раскрывает противника.

Слуховое обнаружение: StalkerAudio2D сообщил о действительно проигрываемом сигнале с достаточным уровнем. Остановленные/приглушённые до порога, muted или virtual каналы такого сообщения не дают. Стена ослабляет реальную громкость/фильтр существующего звука, поэтому слышимый из-за стены монстр может вызвать угрозу — он уже выдал себя звуком.

Угроза держится несколько секунд после восприятия. Бой возникает от воспринятой подготовки атаки, одного замеченного преследователя в Close Combat Distance, Crowd Enemies For Combat замеченных преследователей в пределах Awareness Distance, выстрела при уже известном агрессивном враге или реального повреждения игрока. Стрельба в пустой комнате сама по себе бой не включает. Последний смертельный выстрел учитывается до исчезновения врага из очередного опроса.

После замечания пользователя о неслышном переходе усилены Threat/Combat, ускорен вход и смягчён duck. Прежний слой угрозы давал лишь около1.5дБ прироста суммарной средней энергии относительно исследования (оценка независимых слоёв), а повторные сигналы испуга снижали весь фон до45%. Теперь вход угрозы даёт около3.3дБ, бой около8.8дБ до duck; это расчёт уровней, а не гарантия субъективного восприятия. Три фоновых канала имеют priority120: при лимите32 реальных голосов они важнее idle/перебора ног, но уступают атаке, ранению и оружию. Числа приоритетов в Unity работают наоборот: меньшее число важнее.

Для диагностики в Play выбери LevelAudioDirector2D: Mood показывает выбранную фазу, Perceived/engaged — учтённых/преследующих врагов, три Gain — фактические уровни каналов. Если Mood меняется, а разница недостаточна, регулируй профиль; если остаётся Explore при контакте, это проблема обнаружения/привязки, её нельзя исправлять только громкостью.

Музыкальная память и постоянная агрессия AI — независимые данные. Контроллер не вызывает ActivateAggro, не возвращает врага домой и не сбрасывает преследование.

Выстрел, ранение и важные слышимые реакции сталкера кратко приглушают фон. При смерти игрока фон затухает; при новой сцене начинается новый контроллер. Time.timeScale=0/AudioListener.pause приостанавливают фоновые каналы. Это не реализация меню паузы/переназначения всего управления. Смена аудиоустройства перезапускает три петли совместно.

## Шаги и поверхности

Шаги зависят от реального перемещения Rigidbody2D. Нажатие WASD в стену, неподвижность, телепорт и смерть не добавляют контакты. У двух вариантов каждой поверхности небольшой разброс pitch, мгновенный повтор варианта исключён.

Без разметки используется Concrete. Для дерева или плитки создай отдельный пустой объект Floor audio area, добавь BoxCollider2D как триггер и GroundAudioSurface2D. Настрой Surface, Priority и размер области. Более высокий Priority выигрывает в перекрытии. Не ставь этот компонент на физическую стену: он превращает свой BoxCollider2D в триггер. Области фильтруются по сцене.

Тип пола отличается от материала цели пули. Для деревянного ящика выбери ImpactSurface2D.Material=Wood; обычные стены по умолчанию Concrete. Сталкер владеет звуком собственного ранения через Damageable2D.OwnsHitAudio, поэтому пуля второй мясной звук не накладывает.

## Как устроен C# в этой системе

- AudioMoodProfile и PlayerWorldAudioSet — ScriptableObject: ссылки на звуки и общие настройки. Они не хранят текущую агрессию или фазу прохождения.
- LevelAudioDirector2D — MonoBehaviour одного уровня: наблюдает источники, удерживает состояние, плавно меняет громкости трёх сохранённых AudioSource.
- AudioThreatEmitter2D — небольшой контракт/реестр: «жив ли источник, преследует ли он, атакует ли, кого он атакует и был ли его звук слышим».
- StalkerAudioThreat2D — адаптер: переводит конкретные свойства ShadowStalker2D и события его звука в этот контракт.
- PlayerFootsteps2D отвечает только за контакты с полом; PlayerUtilityAudio2D — за фонарь/пустой спуск. Существующий PlayerAudio2D сохраняет пистолет/гильзы/импакты/подбор.
- AdaptiveAudioSetup — одноразовая редакторская миграция. Она сохраняет компоненты/объекты в сцене и префабах. Во время игры уровень или источники не строятся.

Событие в C# — уведомление подписчикам о факте. Например, ShotFired сообщает контроллеру и звуку об одном совершившемся выстреле; подписчики не решают, потрачен ли патрон. HealthChanged приходит только после принятого повреждения, PowerChanged — после фактической смены питания, EmptyTriggerPulled — на пустом спуске с ограничением частоты.

Это похоже на addEventListener/removeEventListener во фронтенде:

```csharp
private void OnEnable()  { weapon.ShotFired += OnShot; }
private void OnDisable() { weapon.ShotFired -= OnShot; }
```

Знак += подписывает метод, -= отписывает. AudioMood — enum: фиксированный набор Explore/Threat/Combat вместо строк с возможными опечатками. abstract AudioThreatEmitter2D задаёт обязательные свойства адаптера; конкретный класс переопределяет их через override, а AI остаётся самостоятельным компонентом.

При выключении компоненты отписываются. Это предотвращает повторные вызовы после включения/перезапуска. Для фона выбраны три постоянно синхронно играющих слоя: изменение громкости не перезапускает файл и не дёргает начало фактуры. Стыки коротких исходников обработаны заранее, PlayScheduled запускает одинаковые9-секундные петли вместе.

Для нового вида врага добавляется отдельный адаптер AudioThreatEmitter2D и сообщение ReportHeard от его реального звука. Переписывать весь контроллер или наследовать AI сталкера не требуется.

## Новые уровни и ограничения среза

LevelRig.prefab уже содержит LevelAudio.prefab; LevelTemplate получает его через rig. Для собственного готового уровня можно добавить LevelAudio.prefab отдельно и назначить Player/Flashlight/Profile. Нужен один контроллер и один AudioListener на сцену.

Новые звуки — пробные сгенерированные foley, не настоящие записи помещения/оружия. Происхождение/задачи/расход11кредитов и обработка — Audio/AdaptivePrototype/Sources.json, Processing.json. Фактурная основа повторно использована без новых генераций. Художественная оценка всех новых сигналов остаётся за пользователем.

Пока нет музыкальных тем меню, ордового сценария, отдельной Safe Area, общего меню громкости или полноценного AudioMixer-графа. Фон управляется отдельно от существующих игровых источников; полноценный микшер можно добавить для меню настроек. Не добавлены фальшивые далёкие монстры/дыхание героя/вода в постоянную дорожку. Настоящие локальные события окружения можно добавлять по потребности конкретного уровня.

## Проверка

В Audio/AdaptivePrototype/Validation.json отмечаются фактически выполненные проверки; отсутствие слуховой оценки не подменяется проверкой декодирования. AdaptiveAudioProbe — временный Editor-only инструмент, не сохраняется в сцене/не входит в билд. Запись real main mix, если приложена, снята с постановочными позициями/сценарными выстрелами; это не обычное прохождение.

Официальные API: [PlayScheduled](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/AudioSource.PlayScheduled.html), [AudioListener.pause](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/AudioListener-pause.html).
