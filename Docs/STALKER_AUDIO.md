# Звук сталкера: как устроен и как настраивать

Версия 0.8, 14 октября 2026. Выбрана и подключена **«живая мембрана»**. Звук принадлежит врагу: на капсулу игрока его добавлять не нужно. Игрок служит точкой, относительно которой определяются расстояние и сторона звука; единственный AudioListener находится на Main Camera.

## 1. Как проверить результат

1. Открой `Assets/EmergencyShift/Scenes/BasementPrototype.unity`.
2. Нажми Play и кликни Game. У вкладки Game выключи **Mute Audio**, если кнопка включена; в системе должен быть слышимый уровень громкости.
3. Приблизься к сталкеру с выключенным фонарём: движение сопровождается перебором ног; спокойная мембрана звучит отдельными эпизодами с паузами.
4. Посвети на него в пределах страха. После его прежней задержки реакции будет вскрик, затем быстрые контакты ног/прерывистая боль при отходе и тихое сжатие.
5. Позволь приблизиться без света: перед броском слышна раскрывающаяся пасть. Успешный удар сопровождается укусом. Попадание пули вызывает ранение, смерть — разрыв, первые посадки частей — отдельные шлепки.
6. Останови Play перед постоянными правками. Параметры, изменённые в Play, обычно возвращаются после остановки.

Если моб стоит, он не обязан непрерывно звучать. Нерегулярная тишина — часть задуманного поведения. Звук не меняет радиус обнаружения/скорость/агрессию: эти правила по-прежнему у `ShadowStalker2D`. Другие звуки игры — пистолет, дверь, игрок и фон — этой задачей не добавлялись.

## 2. Что находится в проекте

```text
Assets/EmergencyShift/
  Audio/Stalker/
    StalkerMembrane.asset          # Общий набор ссылок и лимиты
    Membrane04/*.wav               # 49 рабочих вариантов,13 групп
  Prefabs/ShadowStalker.prefab     # Сохранённые компонент/источники
  Scripts/
    StalkerAudioSet.cs             # Данные набора
    StalkerAudio2D.cs              # Проигрывание, расстояние, фазы
    ShadowStalker2D.cs             # AI сообщает о событиях
    GoreBurst2D.cs                 # Сообщает о выпущенных частях
    GibMotion2D.cs                 # Сообщает о первом ударе части об пол
  Editor/StalkerAudioSetup.cs      # Разовая настройка/восстановление ссылок
```

На каждом живом сталкере есть следующая структура:

```text
Stalker
  ShadowStalker2D
  StalkerAudio2D
  ...остальные прежние компоненты...
  Audio
    Movement  [AudioSource + AudioLowPassFilter]
    Voice     [AudioSource + AudioLowPassFilter]
```

Эти объекты сохранены в префабе, а не создаются при запуске комнаты. Все 7 существующих сталкеров наследуют их. Четыре статических тестовых трупа не получили AI/звук и молчат. На камере сохранён один AudioListener.

Два канала позволяют шагам звучать одновременно с голосом. В каждом канале одна текущая запись: новый важный голос заменяет старый. Здесь нет `PlayOneShot`, способного незаметно наслаивать много клипов на одном источнике. У погибшего моба перестают запускаться шаги/idle, но звук разрыва может закончиться.

## 3. Где менять громкость и слышимость

В Hierarchy выбери живого сталкера → компонент **Stalker Audio2D**. Для всех будущих экземпляров меняй компонент у `ShadowStalker.prefab` в Project. Настройка одного экземпляра в сцене становится его override; она не обязана меняться вместе с префабом.

| Поле | База | Что меняет |
|---|---:|---|
| Master Volume |1| Весь звук данного врага,0–1 |
| Movement Volume |0.9| Контакты/трение/бросок/посадки частей,0–1 |
| Creature Volume |1| Мембрана, реакции, бой/разрыв,0–1 |
| Distance Per Contact |0.22| Мировое расстояние до следующего контакта: меньше → чаще |
| Minimum Contact Interval |0.075 с| Ограничивает максимальную частоту, без залпа после зависания кадра |
| Friction Chance |0.16| Доля контактов, заменяемых коротким трением; трение дополнительно тише |
| Contact Pitch |1| Незначительная настройка высоты только контактов; скорость движения её не меняет |
| Idle Pause |3–7 с| Новый случайный интервал между попытками спокойного звука |
| Cower Pause |1.3–2.8 с| Паузы между тихими сокращениями в сжатом ожидании |
| Retreat Pain Pause |0.32–0.55 с| Паузы между реакциями боли при отходе |
| Full Volume Distance |2.5| До этой дистанции нет снижения громкости по расстоянию |
| Hearing Distance |11| К этой дистанции звук плавно затихает до нуля, дальше события не запускаются |
| Pan Distance |6| Разница X, достаточная для выраженной стороны в стерео |
| Maximum Pan |0.75| Ограничение крайнего положения слева/справа |
| Blocked Volume |0.45| Доля громкости за высокой преградой |
| Blocked Cutoff |1300 Гц| Срез высоких частот за преградой: меньше → глуше |
| Obstruction Interval |0.15 с| Частота проверки прямой преграды |

Настраивай громкость здесь. Скрипт сам обновляет Volume/Pan у дочерних AudioSource, поэтому ручное изменение тех полей во время игры будет перезаписано.

У шести рабочих шагов одинаковая средняя энергия и смягчённые пики. Трение применяется с дополнительным коэффициентом 0.25, чтобы случайный scrape не стал громким ударом. Акцент на каждом шестом контакте из раннего монтажа убран. Исходная громкость мембраны/остальных утверждённых WAV сохранена. Равная энергия помогает балансировке, но не заменяет прослушивание.

## 4. Как добавлять нового сталкера

1. Перетащи `Prefabs/ShadowStalker.prefab` в сцену. Сохрани пользовательскую расстановку; Audio-дети уже входят в префаб.
2. На `ShadowStalker2D` назначь Player и Flashlight из текущей сцены. Префаб-ассет сам не хранит ссылки на конкретного игрока другого уровня.
3. Проверь Blocking Geometry: высокие стены/дверь находятся в LightObstacles. Параметры ожидания/патруля настраиваются отдельно, как раньше.
4. На `StalkerAudio2D` должны быть назначены Sounds=`StalkerMembrane`, Movement Source/Voice Source и два фильтра. Обычное копирование готового сталкера сохраняет их.
5. На уровне должен быть один активный AudioListener. Уже существующий находится на Main Camera; каждому врагу слушатель не нужен.
6. В Play проверь звук с расстояния, около преграды и при бегстве. Останови Play и сохрани сцену.

Если ссылки случайно удалены, при остановленном Play доступно `Emergency Shift → Audio → Apply approved Stalker audio`. Это редакторский инструмент, сохраняющий ссылки в префабе/сцене. Он не перестраивает геометрию и не сбрасывает поля AI; существующий набор звуков/настроенные ссылки сохраняются. Обычно повторять настройку не требуется.

## 5. Как игра решает, какой звук запустить

| Ситуация | Что происходит |
|---|---|
| Мирное движение/погоня/отход | Накапливается фактическое изменение Rigidbody2D.position; каждые 0.22 единицы — контакт |
| Стоит, зажат физикой или получает короткий stagger | Новые контакты не запускаются; уже начавшийся короткий контакт может закончиться |
| Покой/патруль/погоня | Раз в случайные 3–7 с возможен короткий idle, если канал свободен и есть бюджет |
| Первичный испуг после задержки AI | Один LightFear с усиленным начальным вскриком |
| Реально отступает | Ускоренные контакты по расстоянию и отдельные RetreatPain |
| Сжатое ожидание | Редкий тихий Cower; не бесконечный стон |
| Начало Attacking | Windup — раскрытие пасти до момента урона |
| Фаза атаки 25% | Lunge на канале движения |
| Фаза атаки 42%, урон принят игроком | Bite на голосовом канале; при промахе нет звука разрываемой плоти |
| Несмертельный урон | Hit заменяет текущий голос |
| Переход Dead | Однократный Death, вместо обычного Hit |
| Первое касание части пола | Debris, максимум 3 на труп и не чаще одного за 0.09 с |
| Игрок погиб | Контакты/активные сигналы прекращаются; последний уже начатый укус может закончиться |
| Компонент/объект отключён | Каналы останавливаются, подписки/регистрация снимаются |

Фазы 25%/42% уже существовали в атаке. Мы добавили уведомления в этих точках, не изменяли длительность/скорость/урон. Пуля, прервавшая подготовку, не оставляет отложенный звук укуса: он вызывается только реально состоявшейся атакой.

При ходьбе вверх/вниз/по диагонали считается длина пути, а не одна ось. Большой скачок позиции трактуется как телепорт и не создаёт пачку шагов. Случайность аудио использует собственный System.Random, поэтому не переставляет случайные решения патруля/крови. В одной группе следующий вариант не повторяет только что сыгранный.

Группа Notice из 2 клипов оставлена в общем наборе как запасной материал. Автоматический крик обнаружения не включён: по согласованному брифу главный маркер — движение. Детектора дерева/плитки/металла сейчас нет. Step и Scrape разделены, чтобы такой слой можно было добавить позже без переделки голоса.

## 6. Почему звук настроен через XY

Игровая камера смотрит по Z с расстояния 10 единиц. Стандартный 3D rolloff мог бы считать эту глубину частью расстояния до источника, хотя в нашей игре важно расстояние по полу.

Поэтому AudioSource работают как 2D (`Spatial Blend=0`), а StalkerAudio2D сам считает дистанцию XY до Player и положение слева/справа. AudioListener на камере выводит итоговый микс. Это понятное пространственное приближение для текущего вида сверху, не полноценная акустическая симуляция или HRTF.

Преграда проверяется Linecast по тому же слою высоких объектов, что блокирует взгляд. Закрытая дверь/высокий шкаф приглушают звук и срезают высокие частоты; низкая мебель слоя 9 не становится глухой стеной. Фильтр/громкость меняются плавно, без резкого переключения. Пока это одна прямая проверка, без обхода звука через дверные проёмы/отражений/комнатной реверберации.

## 7. Несколько существ и ограничения

В Project выбери `Audio/Stalker/StalkerMembrane.asset`:

- **Movement Voices=8:** право запускать контакты получают ближайшие 8 движущихся существ.
- **Idle Voices=2:** одновременно не больше 2 тихих Idle/Cower.
- **Death Voices=3:** одновременно не больше 3 основных разрывов; более близкая смерть может вытеснить дальнюю.

Это один общий asset, его изменение касается всех использующих набор врагов. Приоритет Unity выше для предупреждения атаки/первичного света, ниже для фонового idle. Каждый враг всё равно использует максимум 2 собственных AudioSource, не бесконечную стопку one-shot. У статических останков нет постоянно играющих компонентов.

Контролируемая проверка 20 экземпляров касается звука и лимитов. Она не доказывает, что навигация/боевой баланс/производительность 20 врагов уже готовы. Нужны отдельные игровое прослушивание группы и Profiler. Если будут сотни трупов, понадобится также будущая политика срока жизни самих останков.

## 8. C# по шагам — что это значит

**AudioClip** — данные WAV после импорта. **AudioSource** — проигрыватель. **AudioListener** — приёмник итогового звука. Импорт файла сам по себе не запускает его в игре.

`StalkerAudioSet : ScriptableObject` — общий объект данных, примерно как JSON-конфигурация во фронтенде, только со ссылками на Unity-ассеты. Он хранит массивы вариантов и общие лимиты. Одни 49 ссылок удобнее редактировать здесь, чем копировать на каждого из 7 врагов.

`StalkerAudio2D : MonoBehaviour` — поведение конкретного объекта на сцене. Его `[SerializeField] private ...` видны в Inspector и сохраняются Unity. `private` защищает поле от произвольной записи другим кодом; SerializeField разрешает настройку редактором. Сохранённое значение сцены/префаба имеет приоритет над начальным значением в исходнике.

`enum Cue` перечисляет допустимые события: Step, Idle, Windup, Death и другие. Это типизированные имена, чтобы не искать звук по строке с возможной опечаткой. `AudioClip[]` — массив вариантов одной группы.

AI объявляет событие:

```csharp
public event System.Action<BehaviourState> StateChanged;
```

Это список подписанных функций, которым передаётся новое состояние. Внутри Enter контроллер обновляет State и уведомляет слушателей, только если состояние действительно изменилось. Звуковой компонент подписывается:

```csharp
stalker.StateChanged += OnState;
stalker.Damaged += OnHit;
```

По смыслу похоже на addEventListener. В OnDisable соответствующее `-=` убирает подписку, как removeEventListener/cleanup во фронтенде. Это предотвращает повторные реакции после отключения/включения и удержание лишних ссылок.

Жизненный цикл компонента:

1. **Awake:** получить ссылки на AI/физику, подготовить источники и собственный генератор случайных чисел.
2. **OnEnable:** подписаться на события и зарегистрироваться для бюджетов.
3. **Update:** обновить слышимость, накопить путь, проверить редкие таймеры. Здесь нет решения «напасть или испугаться».
4. **OnState/OnHit/OnLunge/OnStrike:** воспроизвести реакцию на фактическое событие AI.
5. **OnDisable:** остановить звук, убрать подписки/регистрацию и ссылки на летящие части.

GoreBurst сообщает о выпущенном GibMotion2D. Тот сообщает о первом касании пола. Так посадка совпадает с физическим событием, а не с предположением «через полсекунды все упали». Звуковой компонент сам ограничивает, сколько посадок стоит озвучить.

Архитектура разделена по настоящим обязанностям: AI принимает игровые решения; данные набора хранят записи; аудиокомпонент оформляет события. Нет singleton, объекта SoundManager, DI или отдельного фреймворка. Небольшой статический список активных аудиокомпонентов нужен только для общих лимитов; он не создаёт уровень и не управляет AI.

## 9. Рабочие исходники и генератор

В игре используются 49 WAV моно PCM24/48kHz. В Unity: PCM, Preserve Sample Rate, Decompress On Load, Preload, Normalize выключен. Так тихая мембрана остаётся тише боли/смерти. Unity может округлять PCM при импорте; исходные WAV сохранены без изменения.

Отклонённые Prototype01/Studies02/Choices03, их генераторы и лишние дубли превью/ZIP удалены. История остаётся в Git. Одобренная графика/анимации/параметры сталкеров не очищались.

Для производства оставлены:

```text
Tools/Audio/generate_stalker_membrane_v04.py
Tools/Audio/stalker_membrane_dsp.py
Tools/Audio/Reference/approved-idle-01.wav
Tools/Audio/Reference/approved-idle-02.wav
Tools/Audio/requirements.txt
```

Python/NumPy2.3.5 нужны только для повторной генерации, игроку/Windows-билду они не нужны. Первые 2 idle берутся из эталонных WAV sample-for-sample. Остальные функции/seed сохранены, все 49 файлов воспроизводятся точно после удаления старых проб.

Из корня проекта: `python Tools/Audio/generate_stalker_membrane_v04.py`. Для осознанной перезаписи добавить `--force`. `.meta` не удалять: они сохраняют GUID/ссылки набора. Обычная настройка звука в Inspector не требует запуска Python.

Для прослушивания отдельного исходника выбери WAV в Project и используй Preview в Inspector. Это сухой звук без игрового расстояния/преград. [Каталог групп](Audio/StalkerMembrane04/stalker-event-catalogue.wav) и [постановочный пример](Audio/StalkerMembrane04/stalker-full-encounter.wav) сохранены для сравнения; это не запись текущей игры.

## 10. Проверка и границы результата

Фактические проверки находятся в [RuntimeValidation.json](Audio/StalkerMembrane04/RuntimeValidation.json), проверка исходников/эталонов — [Validation.json](Audio/StalkerMembrane04/Validation.json). Они отдельно фиксируют наличие ссылок, реальные Play-сценарии и ненулевой DSP-выход Unity. Это не подтверждение звука физических колонок пользователя и не субъективная художественная оценка.

Следующие отдельные этапы: собственные звуки оружия/окружения/двери, микс всего уровня, отдельные материалы контакта, полноценная толпа/Profiler и самостоятельный Windows-билд. При стрельбе слышна реакция врага. В v0.8.1 подбор получил временный звук; отдельные кандидаты выстрела/материалов подготовлены для оценки и выключены по умолчанию. Гайд — AUTO_PICKUP_AND_WEAPON_AUDIO.md.

Документация Unity: [2D/3D AudioSource](https://docs.unity3d.com/Manual/AudioSource-overview.html), [приоритет источника](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/AudioSource-priority.html), [LowPass cutoff](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/AudioLowPassFilter-cutoffFrequency.html), [проверка выходных samples](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/AudioListener.GetOutputData.html).
