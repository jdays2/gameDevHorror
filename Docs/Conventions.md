# Соглашения Emergency Shift

Правила архитектуры — [sod-unity-architecture](../.agents/skills/sod-unity-architecture/SKILL.md), решение — [ADR-001](Decisions/001-sod-architecture.md). Здесь проектные пути и порядок работы; фактические владельцы — в [Features](Features/README.md).

## Папки и зависимости

Production root — `Assets/EmergencyShift`; переименование в `_Project` из SOD не требуется. Runtime/Editor/Development/Tests сохраняют границы сборок. Новый или мигрирующий модуль выделяет Config/Logic/View, Controller и installer по фиче под действующим root; текущая раскладка и незавершённая миграция не скрываются. Model не зависит от MonoBehaviour, камеры, ввода и View. Unity-мотор/физика — адаптер.

Пути/namespace меняются с .meta и проверкой ссылок. Не менять GUID и не регенерировать сцены. Сторонние пакеты не переписываются; различия оформляются адаптером/вариантом. Путь существующего файла не доказывает ни использование, ни неиспользование: проверять source/asmdef/serialized references и Editor-авторинг.

## C# и данные

Формат действующего проекта задаёт [.editorconfig](../.editorconfig); дополнения SOD — [C# и lifetimes](../.agents/skills/sod-unity-architecture/references/csharp-and-lifetimes.md). При полном текущем проходе проверяется весь собственный C#, в обычной задаче — затронутая область. Не форматировать vendored code и Unity YAML массовым текстовым инструментом.

Настройки принадлежат тематическим SO, runtime-состояние — экземпляру. Сценовая расстановка/патрули/локальные override сохраняются. DefinitionId и instance ID различаются; переименование ассета не меняет постоянную идентичность. Формат save требует версии и проверенной совместимости/миграции, а не только переименования поля.

Извне Model меняется через проверяемую команду; ожидаемый отказ — Result. Время/случайность приходят через зависимости. Композиция — Zenject/Extenject с явными сроками жизни. Отписки, отмена async и bounded cache — ответственность владельца. Не вводить скрытый глобальный игрок/статическое mutable-состояние.

## UI, сцены и контент

Игровой UI сейчас uGUI. View показывает состояние и передаёт intent, правила решает Model/команда. Единый Canvas/prefab редактируется в Unity. Текущие Pause/диалог/световые механики сохраняются; запрет паузы из SOD — не правило этой игры.

Документы художественного направления и происхождения — [ART_DIRECTION](ART_DIRECTION.md), [Concepts](../Concepts/README.md). Принятые полы, кровь и аудио не заменяются архитектурным рефакторингом. Исходники/лицензии не теряются. Отчёт о сборке не подтверждает творческую приёмку.

## Документы и Git

Рабочий паттерн владельца и агента — [DOCUMENTATION](Guidelines/DOCUMENTATION.md); подбор skills — [Roadmap/Skills](Roadmap/Skills.md). Код/конфиги, контракт фичи, соответствующий шаг и проверки обновляются вместе. Не дублировать баланс/статус в нескольких общих сводках.

Conventional Commits на английском; один логический шаг в коммите. Только документация — проверка ссылок/диффа/whitespace; код — релевантные тесты, а для runtime/DI/сборок ещё целевая сборка. Чужие незавершённые изменения не включать. Push не повторять после отказа автоматической проверки без нового явного разрешения на отправку.
