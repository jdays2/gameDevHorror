# BUG-048 · Универсальная точка входа

Исторический отчёт. Позднее в тот же день владелец отклонил обязательный вход через меню: Won't do до рабочего билда. Автоматическая политика и связанный автоавторинг откачены в [BUG-049](MenuIsolation49.md); нижеследующие проверки не являются действующим контрактом запуска.

Главное меню закреплено как обязательная точка обычного интерактивного запуска для всех чатов проекта. Политика Editor восстанавливает MainMenu при загрузке/перекомпиляции, перед обычным Play и после выхода из Play. Временный переключатель запуска текущей сцены удалён. Правило записано в проектном AGENTS, маршрутизирующем AGENTS рабочей папки и Notion «Как мы работаем».

## Изменения

- MainMenuSceneRegistry синхронизирует каталог со всеми сохранёнными сценами под Assets/EmergencyShift/Scenes: сейчас 11 маршрутов и само меню первым в Build Settings. Существующие ID и названия сохранены; новые сцены получают GUID как ID. Перед изменением SO проверяется валидность нового снимка. Повторная синхронизация не переписывает неизменённые поля.
- Каталог имеет viewport/mask, вертикальную прокрутку и автоматическое удержание выбранной клавиатурой строки в видимой области.
- MainMenuEditorNavigation запускает сцену через существующую UI-кнопку. ReviewWeaponFx/PickupGlintReview/PickupGlintTiming переведены на этот маршрут; SandboxSceneBuilder больше не делает песочницу первой сценой сборки.
- Новые сцены, включая будущий первый реальный уровень, автоматически появляются в каталоге. Не создавался фиктивный уровень и не менялся маршрут «Новой игры»: пока это чистая MechanicsSandbox.
- Автоматические fixture-сцены Test Runner являются отдельным техническим исключением. В закреплённой версии Test Framework pending-run состояние доступно только внутренним IsRunActive; Editor-адаптер читает его через reflection, поскольку RunStarted происходит уже после выбора Play-сцены. На тестовый вход временно снимается override, после тестов возвращается меню. PlayMode регрессия защищает это условие при обновлении пакета.

## Проверки

- 12/12 EditMode: прежние команды/настройки плюс восстановление сброшенного входа без смены открытой сцены и автоматическое добавление/удаление временной сцены с сохранением ID.
- 1/1 PlayMode: Test Runner действительно запускает свою InitTestScene без MainMenuContext. Два ранних прогона были отменены при проверке раннего исключения; после исправления итоговый прогон пройден. Дубликаты одной записи в ответе Pipeline не считаются дополнительными тестами.
- Отдельно намеренно сброшен playModeStartScene; обычный Play восстановил MainMenu.
- UI-навигация и F8 проверены по всем 11 сценам, включая семь ArtReview. После каждого возврата один MainMenuPresenter, AudioListener и EventSystem. Нижняя строка каталога доступна и видима при выборе клавиатурой. [Маршруты 0–3](../Validation/UniversalMenu48/routes-0.json), [4–7](../Validation/UniversalMenu48/routes-4.json), [8–10](../Validation/UniversalMenu48/routes-8.json).
- Обычная Windows64 сборка всех 12 сцен: Succeeded, 0 errors, 1 warning, 673132053 байт, 21.48 с. Из проектных assembly в Managed только EmergencyShift.Runtime.dll. [Сводка](../Validation/UniversalMenu48/build.json). Предыдущую попытку блокировал диалог сохранения оставшейся InitTestScene; она отменена, служебная сцена закрыта без сохранения, успешная сборка выполнена после очистки.
- Проверочные скрипты ReviewWeaponFx, PickupGlintReview и PickupGlintTiming компилируются без диагностики (dry run). По окончании Editor вне Play, открыта MainMenu, playModeStartScene=MainMenu, в Build Settings 12 сцен. Игровые сцены не сохранялись.

Сохранённые игровые сцены не регенерировались и не сохранялись этим исправлением; чужие незавершённые изменения не включаются в его коммит. Прежний художественный вид и музыка меню сохранены. [Фактический контракт](../Features/MainMenu.md).
