## Исходное поведение

В обычном Play открытой MechanicsSandbox через LevelContext созданы штатные Door/ShadowStalker/Sleeper prefab в изолированной позиции. Использован настоящий Door.Interact с PlayerInteraction. Для чистого наблюдения выталкивания locomotion особи остановлена, живые Rigidbody2D/collider сохранены. Сталкер был вытолкнут с x=600.2 до 600.7349, Спящий — до x=600.7349/y=614.3062. После полного закрытия здоровье осталось 2/8, кровь не появилась. [Baseline](../Validation/DoorCrush01/baseline.json).

## Реализованная граница

Door2D сообщает предлагаемый шаг до записи Transform. Чистые DoorCrushModel/controller разрешают только настоящий шаг закрытия; восстановление/disable-snap не выдают это разрешение. Отдельный opt-in Physics2D-адаптер проверяет исходное перекрытие и весь sweep фактического BoxCollider2D. Расширенного радиуса опасности нет. Из результата исключены triggers и другая сцена; growable lists не обрезают число контактов.

Все смерти идут через общий EnemyHealth2D.Kill/DamageHealthCommand. В общей двери нет выбора Stalker/Sleeper, прямого вызова gore или игрока. Одно здоровье подтверждает смерть, прежние AI-адаптеры останавливают физику/бой, прежние эффекты/аудио создают один разрыв. Новый тип с этим контрактом не потребует новой ветки двери; его собственный lifecycle всё равно требует проверки prefab. Config принадлежит авторенной створке и действующим readonly профилям duration/gore/audio, runtime-коллекции — одному компоненту и очищаются после шага/disable. Новых чисел баланса, save payload, статического реестра целей и пулов нет.

Контракт — [Doors](../Features/Doors.md#раздавливание-монстров). Объяснение границы: дверь определяет физический контакт, здоровье решает единственный переход в смерть, а останки остаются у уровня. Поэтому дополнительные коллайдеры не создают дополнительные смерти/кровь.

## Сборка и пределы

Окончательная обычная Windows64: **Succeeded, 0 errors, 1 warning**, 11.379 s, `build_e0b6d6a96010`. Предупреждение ожидаемое: RuntimePipelineConfig отсутствует, сервер Pipeline выключен в Player. Из собственных assembly включена только EmergencyShift.Runtime.dll. Собственный standalone Player запущен и завершён после startup smoke, стартовых exception нет. [Сборка](../Validation/DoorCrush01/build.json), [startup/assembly boundary](../Validation/DoorCrush01/player-startup.json). Игровые контакты выше проверялись в Editor.

Синхронная первая сборка завершилась, но запрос Pipeline превысил 30 s; незапущенный временный callback отменён. Окончательная сборка выполнена штатным async `unity command build`, затем `build_status`, с единственной явно выбранной DoorCrushTest и обычными флагами. Подробный native report и стартовый лог остаются в `work/door-crush01`.

Поддерживается solid XY BoxCollider2D без skew и Edge Radius. Отдельного поведения смерти игрока нет. Не добавлены auto-checkpoint, кампания, pool/ECS, OPT-01 или гарантии FPS для толпы. Для использования — [инструкция](../Guides/DOOR_CRUSH_TEST.md). Художественная оценка момента/останков и удобства ловушки остаётся владельцу.
