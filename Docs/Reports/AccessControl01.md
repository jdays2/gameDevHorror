# Карты и считыватели · MVC/DI · BUG-019

Дата: 2026-10-21. База `74cd34a`. Сценовые GUID, требуемые ID/названия карт, расстановка, обратная совместимость checkpoint и параметры считывателя сохранены.

## Границы

`AccessCardModel` содержит только личное множество ID. Add/Restore проходят команды с `CanExecute` и `CommandResult`; снимки копируются, сортируются Ordinal и не открывают живую коллекцию. `AccessCardController` уведомляет интерфейс View только после принятой операции. `PlayerAccessCards2D` сохраняет старый публичный API и событие Changed, делегируя правила модели.

`DoorAccessModel` хранит личную разблокировку и два независимых cooldown. Controller получает `IGameClock`; команды проверяют время и разрешают чтение/тихое восстановление. Immutable `DoorAccessSettings` копирует требуемый ID и интервалы. `DoorAccess2D` разрешает Unity-ссылку на карты актёра и отображает результат (звук/уведомление/подсказку); Time и правила доступа убраны из компонента. Одно успешное чтение навсегда открывает замок данной попытки; восстановление не проигрывает сигналы. Движение створки остаётся отдельным последующим переносом.

`AccessControlInstaller` установлен в LevelContext. Общие stateless-фабрики создают отдельную модель для каждого инвентаря/считывателя, без singleton-состояния игрока и service locator. Конструкторы controller имеют по две зависимости; Card View не подписывается на внешние источники и принадлежит своему компоненту.

## BUG-019

До исправления четыре настоящих отрицательных EditMode показали, что прямой Restore не отклоняет null/пустой/пробельный/повторяющийся ID. Теперь проверка предшествует замене множества и общему player Restore: здоровье и карты не меняются при отказе. `null` вместо всей коллекции остаётся поддерживаемым legacy-пустым набором. Форматы 1/2/3 и строковые ID не переименовывались.

## Проверки и ограничения

**502/502 EditMode**: исходные четыре отказа стали проходить; дополнительно проверены прямая и checkpoint-валидация, повторная проверка команды, защита копий, личные модели, независимые cooldown и границы времени. **17/17** полного PlayMode и **1/1** новой проверки реального LevelContext/MechanicsSandbox прошли отдельно на одном runtime-коде. Последняя проверяет два инвентаря и два считывателя, успешное чтение и отсутствие повторного сигнала после удаления карты. Проверка двери выполняется через настоящий адаптер, без её физического движения. Обычный Windows64 Player — [AccessControl01.json](../Validation/AccessControl01.json).

Старые PersistenceTests и BloodPoolTests перечитаны целиком и проверены в общем прогоне. Их исторические замечания о непокрытых повреждённых payload закрываются существующими отдельными regression fixtures; эти два файла сами по себе не обязаны дублировать весь suite.

Рабочая копия включает прежнюю принятую незакоммиченную паузу. Полный MVC других фич, оставшиеся legacy-конфиги, движение двери, полный маршрут/слуховая оценка и авторская приёмка этим отчётом не закрываются. Profiler/FPS не измерялись.

Цена: личные небольшие модели вместо коллекций и таймеров в MB; команды выделяются при действиях/восстановлении, не каждый кадр. HashSet для проверки и копии массивов создаются на загрузке/снятии snapshot. Новых Update, coroutine, сценовых поисков и фоновых задач нет.
