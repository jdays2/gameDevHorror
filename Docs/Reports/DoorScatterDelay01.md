# TASK-004 · Индивидуальные задержки разбега

После полного открытия двери MorgueRouteTest участники начинают свои маршруты по очереди: Stalker_Intro — 0 s, Stalker_Hall02 — .2 s, Stalker_Hall01 — .45 s, Stalker_Hall03 — .7 s. Новое поле Start Delay Seconds редактируется на личном ScriptedStalkerRoute2D; общие профиль и prefab не менялись.

## Граница поведения

Личный ScriptedRouteModel хранит startDelayLeft и состояние WaitingToStart. До первого выполненного условия таймер не расходуется; StartScriptedRouteCommand фиксирует запуск один раз. Пока он идёт, controller задаёт остановку через прежний motor, глаз остаётся открыт и обычные агрессия/атака/патруль подавлены. После ожидания начинается отдельная реакция либо сразу движение. Ноль сохраняет прежнее поведение, отрицательные/нечисловые значения отклоняются на границе модели. Inspector показывает остаток времени.

Свет, урон, stagger и смерть обрабатываются прежним actor loop. Stagger приостанавливает таймер и исполняет толчок; смерть/недоступная цель отменяет маршрут. Никаких Coroutine, общего таймера группы, второго владельца Rigidbody и нового checkpoint payload нет. Сама задержка не запускает световую анимацию или EyeBurn. Физическое тело остаётся обычным и может быть толкнуто соседом; очередь рассчитана на текущую авторскую расстановку.

## Финальный аудит и закрытие TASK-004

По поручению владельца от 2026-10-24 повторно просмотрены модель/контроллер/команды, видовой мост, фабрика, Inspector, проверки и документация. Личный таймер принадлежит модели, сцена хранит индивидуальные настройки, общий SO не меняется. Один actor loop/motor остаётся владельцем движения; повторные условия не сбрасывают запуск, отмена и освобождение не оставляют отложенной работы. Нет Coroutine, новых Update, LINQ/поиска сцены в горячем пути или зависимости runtime от Editor. Нулевое значение и прежние индексы enum сохранены. Замечаний, требующих изменения игровой логики задержек, не осталось.

Найден и воспроизведён BUG-052: повторный запуск VerifyDoorScatterDelay после коммита ошибочно пытался подготовить исходный патч и падал на уже существующем поле. Теперь обычный запуск выполняет только проверку, не пишет файлы и не зависит от старого HEAD. Генерация отдельная, с обязательной парой `--patch-base` / `--patch-output`; новая база/путь выбираются явно. Существующий вывод и путь вне проекта отклоняются. Исходные JSON/patch проверки не перезаписываются.

Authoring probe приведён к читаемому оформлению. Все ожидаемые ID и DoorOpened проверяются до первого изменения; Restore не закрывает неожиданную additive-сцену, ошибка SaveScene явно обрабатывается. Его последующие снимки и восстановительные копии пишутся только в `Temp/DoorScatterDelay01/`. Четыре собственных временных файла перенесены туда из Docs; исторические tracked-свидетельства остались побайтово прежними.

[Итог аудита](../Validation/DoorScatterDelay01/final-audit.json): повторная проверка прошла дважды; SHA256 всех исторических свидетельств совпадают; явный патч по базе до изменения побайтово совпал с исходным; повторный вывод, неверная база, неполная пара аргументов и путь вне проекта отклонены без записи.
