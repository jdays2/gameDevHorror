# Модули фонаря · MVC/DI

Дата: 2026-10-21. База `7f2425e`. Перенос существующих правил, без изменения оптики сцены, расстановки или формата сохранения.

`FlashlightUpgradeModel` — чистая личная коллекция ID/суммарных бонусов и число установок. Установка и восстановление проходят команды с `CanExecute`/`CommandResult`. Controller связывает их с узким интерфейсом текущего фонаря: доступность, текущая оптика, текущие лимиты и применение результата. У controller две зависимости, нет View/Unity object в модели, глобального состояния и поиска сцены.

`FlashlightControllerFactory`/`FlashlightInstaller` подключены через LevelContext; для каждого компонента создаётся отдельная модель от начальной оптики. `FlashlightUpgrades` сохраняет сериализованные maximumRange/maximumAngle и старый публичный API, отображает сообщение и применяет готовые значения. Лимиты считываются в immutable value при действии, поэтому их ручное снижение не ухудшает уже имеющуюся дальность при следующем подборе. Общая SO-миграция legacy tuning остаётся отдельной незавершённой частью.

Повторяемый ID накапливает бонусы под одной записью и увеличивает count при каждой установке. Неповторяемый ID, недоступный актёр, неверные числа и отсутствие улучшения отвергаются без изменения состояния. Бонус под одним ID остаётся конечным; счётчик не переполняется. Восстановление проверяет весь набор до замены, возвращает оптику от базы и не зависит от текущего игрового gate. Сохранён прежний `ModuleState { id, bonus }`, старые null-наборы/count и player-format1/2/3. `FlashlightModuleValidation` теперь только адаптирует прежний DTO к единому чистому валидатору.

**519/519 EditMode**, включая 17 новых независимых проверок правил; **19/19 PlayMode**. В новой проверке загружается настоящий MorgueRouteTest: начальное отсутствие фонаря → получение → +1 к дальности → восстановление модулей/базы и владения. Реальная CameraFollow2D даёт больший обзор на каждом шаге и возвращает исходный размер без фонаря; включение света при улучшении не сбрасывается. Это прямые вызовы существующего API после штатного Start, без физического прохода к предмету, сглаживания zoom и зрительной/балансовой приёмки. Первый запуск теста ошибочно вызывал камеру до Start; исправлена только эта предпосылка fixture.

Windows64, точные результаты/хеши и сохранность прежних ресурсов — [FlashlightUpgrades01.json](../Validation/FlashlightUpgrades01.json). Отдельная копия включает прежнюю принятую незакоммиченную паузу. Пользовательские слоты не используются; обе реальные тестовые сцены не содержат checkpoint-контроллера, временные загрузки выгружаются. Общая миграция самого Flashlight2D, камеры, AI и других систем продолжается.

Цена: личная модель/controller вместо словаря в MonoBehaviour. Команды создаются при действиях; дополнительный value-массив используется при переходе старого checkpoint DTO к чистым данным. Это не каждый кадр. Новых Update, обходов мира, VFX или аудиоисточников нет. FPS/Profiler не измерялись.
