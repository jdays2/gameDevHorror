# BUG-051 · Разделение подписей Спящего

Проверка 2026-11-02 в Unity 6000.6.5f1. Исходная ревизия — `261c208`, поверх сохранённых авторских изменений общей рабочей копии. После явной передачи общего слота от BUG-046 выполнена целевая правка `MechanicsSandbox`; карта не перестраивалась.

## Причина и изменение

`Sleeper_BehaviorNote` (GO 1061168066, Text 808270871) и `Sleeper_TargetNote` (GO 1451442419, Text 99122996) были активны в `10_World/R03_WeaponsRange/Notes`, оба в (50; 14.5; 0). Там же находится заголовок «03 · ОРУЖЕЙНЫЙ ТИР». Обычный Play открытой карты и игровая камера подтвердили одновременное наложение трёх текстов — [исходный кадр](../Validation/SleeperNotes51/range-before.png).

Сохранены оба авторских Canvas, полные тексты, дочерние объекты, IDs, scale 0.01, rotation 0, шрифт 32, порядок Canvas 6 и активность. Поменялись только назначения в пространстве:

| Подпись | Новый владелец | World position |
|---|---|---|
| Пробуждение, погоня и прямой выпад | `10_World/R02_AccessTest/Notes/Sleeper_BehaviorNote` | (35.5; 14.2; 0) |
| Неподвижная цель без атак | `10_World/R03_WeaponsRange/Notes/Sleeper_TargetNote` | (56.5; 7.3; 0) |

Описание живого врага размещено отдельно от заголовка и инструкции карты, над живым тестом. Подпись неподвижного — над целью (57; 5), с промежутком до остальных обозначений. Первый вариант позиции возле прохода отклонён при осмотре; окончательные координаты проверены повторно.

Актёры не менялись: живой остаётся (35; 11), неподвижный — (57; 5), оба по 8 HP. У цели прежние `attacksEnabled=false`, `FreezeAll`, disabled CrowdAgent; у живого сохранены атаки и CrowdAgent. Prefab, все overrides и два persistent IDs совпадают с исходным native-снимком.

## Проверка

- Обычный Play одной открытой `MechanicsSandbox`, `playModeStartScene=null`; MainMenu не загружался. Для воспроизводимого осмотра герой перемещался только в runtime, камера следовала с обычным zoom 4.6. Это контролируемый осмотр, не полное прохождение маршрута.
- Игровая камера: [тир после](../Validation/SleeperNotes51/range-after.png), [живой тест после](../Validation/SleeperNotes51/live-after.png), [цель после](../Validation/SleeperNotes51/target-after.png), [цель под фонарём](../Validation/SleeperNotes51/target-lit-after.png). Кадры после — 1920×1080, 16:9. Дополнительно через computer-use осмотрено само окно GameView с HUD: обе подписи читаются в соответствующих тестах, противоречивого наложения нет.
- Настоящая сцена/цель: `ReceiveBulletHit(1)` даёт 8→7 HP, Sleeping→Waking→Hunting, один голос пробуждения. За 4.5 s максимальное отклонение позиции менее 0.00000385 units, выпадов и завершённых атак 0, HP героя 100→100. Затем 7 урона: Dead/0 HP, один DeathCount, 14 частей останков в итоговом повторе (17 в первом прогоне), settled=true. Это реальный AI/physics/death pipeline, с контролируемой подачей попадания — не проверка наведения и стрельбы оружием.
- Отдельный свежий Play с настоящим фонарём героя: через 3 s Hunting/агрессия, 8 HP, смещение 0, выпадов 0, HP героя 100→100, один WakeCount. Начальный пробный assert зафиксировал переход диапазона HP 3→100 до срабатывания триггера тира; после ожидания обработки trigger повтор прошёл. Это ошибка времени измерения пробы, а не изменение здоровья цели.
- Итоговый контроль авторинга выполнен в фактической остановленной сцене, включая неактивные объекты: 714 Transform, правильные родители R02/Notes и R03/Notes, обе сборки Canvas целы, missing scripts/references=0, duplicate persistent IDs=0. Исходная сцена имеет GUID `6bd59672b95738b4889d0eb563c60527`.
- Сравнение сериализации: 664→664 блока, 0 добавлено/удалено; изменены только `3628977`, `1061168067`, `1349773415`, `1451442420`. Остальные 660 блоков идентичны. Геометрия, коллизии, сортировка, освещение/звук, актёры и маршруты не менялись. 23 прочих dirty tracked файла сохранили исходные SHA-256.
- Отдельный Git payload содержит только эти четыре изменения поверх HEAD: 663→663 блока. Нативный preview этого состава: 701 Transform включая неактивные, 0 missing scripts/references, правильные две подписи и прежние два актёра. Отличие количества от рабочей сцены относится к чужому сохранённому содержимому, исключённому из коммита; рабочая сцена не заменялась payload.
- После Stop повторный native-контроль: одна исходная сцена, dirty=false. Текущая Console: 0 errors / 0 warnings, compilationFailed=false; исторический Pipeline buffer содержит пять прежних диагностик команд предшественника, новых записей error после cursor 24 нет. Runtime/assembly/package/config не менялись, поэтому общий test suite и новая сборка не запускались. Художественная приёмка владельца не подменяется этими проверками.

RectTransform сохранялись через native SerializedObject с `m_AnchoredPosition`: первая запись через `Transform.position` до layout-прохода оставила отложенные позиции dirty. Перед продолжением сохранена отдельная native-копия; сравнение доказало, что отличались только два наших anchored-position. Посторонние unsaved edits не сохранялись и не отменялись. Финальная запись и повторный Stop подтвердили сохранённые координаты без dirty-состояния.
