# Роли менеджера и исполнителя · 2026-11-03

По прямому поручению владельца текущий чат «Обновлять задачки» использует manager, новые чаты задач — worker. Роли реализованы reusable skills и AGENTS routing, не приложением UI-тега или изменением permissions.

## Изменение

- Добавлены emergency-shift-manager, emergency-shift-worker и общий emergency-shift-coordination. Запуск исполнителя требует только роли, кода/ссылки и особых требований.
- Убрано обязательное чтение всех Unity/migration/art/SOD skills из управления задачами. Исполнитель читает только применимые skills/references; старые инструкции о чтении на каждой проектной задаче согласованы.
- Один протокол: [CHAT_COORDINATION](../Guides/CHAT_COORDINATION.md). Параллельные чтение/анализ и непересекающиеся внеимпортные результаты; последовательный game/Editor доступ, отдельные path/git резервы. Одного знания роли или idle недостаточно для мутаций.
- Атомарный cooperative coordinator хранит текущую очередь/lease вне Unity и Git проекта. Он не является sandbox или источником разрешений, не имеет TTL/автоматического захвата чужого слота и не запускает процессы. Notion сохраняет планы/критерии; реестр хранит только операционное владение.
- Canonical skills находятся в project `.agents/skills`; три роли зеркалированы в workspace `.agents/skills` для внешнего CWD и установлены в личную `.codex/skills`. Пять существующих SKILL.md синхронизированы без замены дополнительных ресурсов/чужих изменений.
- Корневой и проектный AGENTS, workflow/migration/content/level/SOD routing, NOTION_WORKFLOW, Skills index и правила Notion согласованы.

## Проверка

- Штатный skill-creator quick_validate: 8/8 skills прошли. Отсутствовавшая зависимость PyYAML установлена только в игнорируемый `work/roles-validator-deps`, не в проект Unity или системный Python.
- Изолированные coordinator checks: 9/9. Проверены два конкурирующих git-захвата (ровно один победитель), запрет game takeover, явный handoff/очередь, пересечение directory/child с учётом регистра, независимые документы, запрет обхода game через files, отсутствие expiry после выхода процесса, rollback неуспешной транзакции и повторное вступление worker.
- Fixtures создавались в `work/roles-tests` и удалялись только после проверки принадлежности этому каталогу. Реальный реестр тестами не затронут.
- Синхронизированные файлы проверены по содержимому; относительные Markdown-ссылки затронутых инструкций проверены, diff whitespace проверен.

## Текущая миграция и сохранность

Менеджер согласовал с TASK-007 отдельные instruction/docs пути. Game/Editor остался у TASK-007, далее TASK-008. Это состояние записано в `outputs/.coordination/EmergencyShift/state.json`; оба исполнителя уведомлены о протоколе. Git-окно менеджера согласовано отдельно; после целевой фиксации оно освобождается.

Эта настройка не меняла C#, Assets, сцены, игровые параметры или живой Editor. Исходная чужая строка в Docs/README сохранена в рабочей копии и исключена из этого коммита. Верхний workspace AGENTS и discovery-копии находятся вне вложенного Git-репозитория и применены отдельно. Итоговый контроль сценового авторинга: неприменим.

Skills могут потребовать обновления списка в конкретном клиенте; AGENTS и явный canonical SKILL.md путь остаются fallback. Работающие чаты должны прочитать новые правила: обновление файла не переписывает их старую историю автоматически.

## Основания

[Official skill discovery](https://learn.chatgpt.com/docs/build-skills) и [project customization](https://learn.chatgpt.com/docs/customization/overview) подтверждают skills/AGENTS как переиспользуемые инструкции. Конкретные роли и cooperative leases — соглашение этого проекта по поручению владельца, не заявленная функция автоматических UI-тегов.
