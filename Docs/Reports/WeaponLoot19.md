# Оружейный лут и дополнение BUG-013

Дата: 2026-10-21. База `bb903f9`. WeaponLootModel хранит личные remaining/consumed/busy, controller и collect/configure/restore commands управляют их изменением. Native WeaponLootPickup проверяет actor/LOS и вызывает существующий оружейный инвентарь; shared definitions не меняются. Частичный сбор уменьшает только фактически принятые патроны, полный запас оставляет коробку, оружейный pickup поглощается только при успешном Acquire. Busy действует также во время feedback; reentry/configure/restore из callback отклоняются.

Найден пропущенный случай BUG-013: WeaponLootCheckpoint2D проверял лишь format, принимал отсутствующие consumed/remaining и отрицательный remaining; прямой Restore не вызывал Validate вообще. Baseline **4/13 passed, 9 failed**. Карточка BUG-013 повторно открыта, без дубликата. Теперь общий consumed presence guard и отдельная remaining sentinel-проверка используются одним Read до любых изменений, в Validate и прямом Restore. Формат1/SaveKey/saveRevision сохранены; полные старые false/zero и consumed=true с остатком оружейного pickup поддерживаются.

Public Configure по-прежнему может менять тип/amount после composition, сохраняя consumed; неверный enum/отрицательный amount отклоняются до записи полей. Прямой legacy RestoreState сохраняет clamp отрицательного remainder к нулю; checkpoint payload проверяется строже и отклоняет отрицательное значение до этого фасада. Serialized cartridges теперь остаётся авторским начальным значением; текущее количество доступно через RemainingCartridges/снимок модели. Item config bridge и concrete actor/weapon refs ещё открыты.
