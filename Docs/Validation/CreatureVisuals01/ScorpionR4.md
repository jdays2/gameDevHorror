# TASK-005 · Скорпион r4 · матовая серо-зелёная версия

Историческое свидетельство: заменено [r5](ScorpionR5.md).

Уточнения владельца: красное самосвечение десяти глаз; настоящая клешня с широкой ладонью, неподвижным отростком и отдельным шарнирным пальцем; смыкание с обеих сторон за счёт доворота ладони; пять сегментов хвоста, луковица и загнутое жало. Позднее владелец попросил уменьшить детализацию и разрешил подобрать зеленоватую палитру. Выбраны холодный серо-зелёный, костяные кончики и красные глаза; убраны мелкие прожилки и мокрые блики, сокращены складки. Ранняя r3 сохранена в history-r3.

Источник — Concepts/Unused/Visual/Scorpion01. Клешни и хвост зарегистрированы как собственные нативные части по заранее объявленной схеме; первые сырые рисунки не прошли наложение и не объявлены готовыми мастерами. На первых пальцах были лишние круговые суставы, их нет в итоговой коже. `r4-native-registration.json` разделяет UV-координаты рисунков и геометрию конструкции. `r4-generation.json` хранит все точные промпты встроенного image_gen, `eye-emission-regions.json` — области эмиссии десяти глаз. Кости → объёмы → 40 функциональных групп/крепления → кожа → 24/16 кадров просмотрены отдельно.

Префаб: тело и глаза — два SpriteRenderer, один Animator; глазные атласы уменьшены до ячейки256², тело512². Материал EyeGlow использует существующий шейдер Prop Emission. Десяти отдельных источников света нет. Сцены не менялись; импорт создаёт только ассеты через собственную PreviewScene. [Свидетельство импорта](scorpion-r4.json). Режим «Ночь» в HTML затемняет тело и отдельно рисует эмиссию; это художественная демонстрация, не нативный замер освещения уровня.

## Нагрузка: оценка по устройству, без нагрузочного теста

По прямому поручению владельца не запускались Play, Test Runner, стресс-сцена, Profiler или FPS-замер. Офлайн экспорт рисунков и импорт prefab-ассетов не измеряют производительность игры.

Расчёт IK/мышц/сетки выполняется при подготовке PNG. В Unity показ кадра не решает физику восьми ног. У одной особи два renderer; у10 —20, у20 —40. Это количество объектов отрисовки, не обещание такого же числа draw calls: фактическое объединение зависит от материала, порядка и рендера. Атласы одного вида общие для всех экземпляров, не копия на каждого врага. GPU использует импортированный формат, а не размер исходного PNG; [документация Unity о форматах памяти](https://docs.unity.com/en-us/engine/6000.7/manual/materials-and-shaders/textures/textures-getting-started/texture-compression-formats/fundamentals).

Для нынешних размеров трёх цветных текстур и трёх эмиссионных теоретический объём — около14.19MiB при8bpp или56.75MiB при RGBA32 без mipmaps, плюс служебные данные. Это арифметика по размерам, не снятый расход VRAM и не гарантия выбранного формата устройства. Число одинаковых врагов не умножает эти атласы на10/20.

Саму смену кадров для10–20 особей разумно ожидать сравнительно дешёвой. Полный бой добавит движение, поиск пути, раздвигание толпы, коллизии, свет, пули и кровь; сейчас у этого визуального префаба такого AI нет. Конкретные FPS без машины и замера не обещаются.

Массовая смерть вероятнее создаст пик:20 врагов ×12 частей =240 летящих фрагментов (пример бюджета, не внедрённый набор смерти Скорпиона). Текущий `GibMotion2D` двигает их самостоятельно и делает CircleCast по препятствиям каждый активный кадр, затем отключает Update после оседания. Есть общий бюджет создания, но он не ограничивает автоматически общее число уже летящих частей. Осевшие останки продолжают занимать память и отрисовываться. Это основание ограничивать число крупных частей при будущем создании набора, а не обещание готовой оптимизации массовой смерти.

Художественная приёмка владельцем не подменяется осмотром. Итоговый контроль авторинга: неприменим — авторенные объекты сцен не добавлялись и не перемещались. Notion пропущен по прежнему поручению владельца.
