## Рекомендация направленного перекрытия: preview, не финальный экспорт

Одноразовая проверка выполнялась только в памяти, без перезаписи исходников, PNG или inspection. Использованы сохранённые позы `measurements/*/*.json`, исходная поверхность `chela-source-r5.png` и существующий `render_chela`. В source512² шарнир находится в(165,200). Проблемные выходные точки(331,281)/(332,281) соответствуют примерно mainUV(131.9,204.6)/(134.8,205.0), jawUV(132.2,206.5)/(135.1,206.7): нижняя левая сторона шарнира, радиусы33.46/30.64 px.

Предложена маска для двух жёстких слоёв:

```python
r = np.linalg.norm(xy - hinge, axis=-1)
hinge_overlap = (r < 28) | ((r < 38) & (xx <= 165) & (yy >= 198))
```

Отдельный поверхностный cap сохраняет круг28: `cap[r > 28, 3] = 0`. Общий круг44 не применяется. В сравнительном preview вариантов28/44/направленный38 фактически осмотрены Attack06, Run08 и Attack16. Направленный вариант закрывает весь бывший ряд до alpha255 и возвращает внутренний проём к контуру малого перекрытия; глубокого44px U-выреза нет. Отдельно подтверждено, что сохранение граничных пикселей cap при r=28 не возвращает щель.

Рендер обеих клешней с направленной маской прогнан в памяти по всем56 позам. Проверка малых замкнутых компонентов alpha<128 не нашла шарнирных просветов; остаётся только известный AA-пиксель Attack14(416,216), alpha116 при смыкании кончиков.
