# Читаемость и следующий рост проекта

15 октября 2026. Разбор после миграции9d92c8b. В этом изменении обновлены правила/skills и IDE-настройки; игровая логика, сцены и баланс не менялись. Открытые замечания ниже не объявляются исправленными.

## Позиция по if и абстракциям

Проблема — растущее число причин менять один участок, скрытый порядок действий и плотность записи. Сам if не дефект. Несколько независимых проверок в шаге укуса могут быть правильнее взаимоисключающей цепочки. Замена else-if на отдельные if без сохранения приоритета меняет поведение.

Выбор реализации по виду врага в оружии/аудио/HUD следует заменять контрактом и видовыми адаптерами. Выбор числового варианта — конфигом. Конечная машина состояний может остаться switch. Условие допуска — именованной проверкой и ранним выходом. Цепочку этапов уровня лучше представлять данными/отдельным вычислением состояния, не вкладывать тернарные выражения.

Краткость означает меньше усилий при чтении. Запись нескольких присваиваний/веток в строку этому противоречит. Корневой .editorconfig теперь задаёт4 пробела, блоковые скобки и раскрытие однострочных блоков для наших C#-файлов; это помощь IDE, не автоматически выполненное форматирование и не семантический анализатор.

«Константы из конфигов» в терминах C# — настраиваемые данные. Баланс/тайминги/радиусы должны иметь один источник в тематическом профиле. Настоящие математические/неизменные технические константы не требуют отдельного SO. Позиции/маршруты индивидуальны, текущее HP/таймеры не записываются в общий профиль.

Это план по обнаруженным границам, не обещание текущей производительности и не разрешение автоматически реализовать OPT-01. Сначала читаемость и жизненный цикл, затем измеряемые узкие места. Текущий ориентир10–20 врагов не требует перехода на ECS.
