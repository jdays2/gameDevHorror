# Мир, фонарь, камера и интеракции

Текущие границы: карты/считыватели, модули и состояние/наведение фонаря перенесены в чистые модели/controller. Физика и представление остаются явными Unity-адаптерами; остальные системы и общие конфиги ещё требуют завершения прохода.

Архитектурная цель — [ADR-001](../Decisions/001-sod-architecture.md); фактическая карта ниже перенесена из ARCHITECTURE без изменения поведения. При кодовой миграции обновлять её по исходникам.

## Остальные связи

`BloodPoolProfile` хранит три подготовленные процедурные формы, stable ID и параметры короткой анимации. `BloodPool2D` выбирает форму и раскладку на смерть; после оседания Update выключен. RemainsRecord остаётся владельцем лужи на уровне. Снимок хранит bloodVariantId плюс прежние трансформы/цвет/видимость; сначала восстанавливаются спрайты, затем осевшее состояние. Старые записи без ID используют прежние круговые спрайты. Порядок 21 renderer slot сохранён. Выбор не зависит от вида brain; новая форма добавляется данными профиля.

Пуля обращается к Damageable2D, поверхность определяет звук. Подборы используют IAutoPickup, двери IInteractable; DoorAccess2D добавляет необязательный замок. Для всех шести карточных дверей MorgueRouteTest назначен DoorAccessFeedbackProfile (сигналы, задержка и микс); DoorAccess2D публикует AccessChecked, DoorAccessFeedback2D управляет отдельным источником считывателя. Door2D удерживает краткое ожидание перед первым открытием и отменяет его при RestoreState/OnDisable. Замки без профиля сохраняют мгновенный старт движения. Данные профиля общие, разблокировка и таймеры принадлежат экземплярам. PlayerAccessCards2D — локальное множество, не глобальный инвентарь.

LevelContext2D — installer сцены; через DI связывает игрока/фонарь, заполняя только отсутствующие авторенные ссылки. Его прежний статический реестр удалён; [world/player scopes](PlayerInput.md) разделены. LevelRig — готовые игрок/камера/Canvas/контекст, LevelTemplate — редактируемая основа. Реестры фильтруются по сцене и очищаются при выгрузке. Геометрия/UI/враги авторятся в сцене, а не создаются bootstrap при каждом Play.

LocalLampAudioSet хранит клипы, громкость и дистанции слышимости. LocalLampAudio2D читает фактическую яркость Light2D после Update света; предыдущая яркость, выбранный контакт, cooldown и два голоса принадлежат экземпляру. Отдельного аудиотаймера мерцания нет. Явный игрок/LevelContext задаёт слушателя в XY; стены глушат звук, OnDisable останавливает голоса. Новый оттенок/радиус или аудионабор не требует изменений AI, камеры и оружия. Больничные трубки имеют LocalLampConfiguration2D с inline LocalLampSceneSettings: цвет, радиус/яркость света, радиус/громкости звука, фаза/мерцание и длина корпуса принадлежат каждому экземпляру сцены. Config применяет значения без собственного Update; Fixture меняет масштаб отдельно от корня света/аудио и сохраняет заднюю кромку у стены. Для этих ламп Settings имеют приоритет над LocalLightProfile и legacy-полями; остальные светильники сохраняют старую схему. Общие SO не мутируют. Подключены две лампы MechanicsSandbox и семь BasementPrototype; [авторинг](../Guides/HOSPITAL_LAMPS.md).

CeilingLightOcclusion2D включён по умолчанию у трёх библиотечных prefab ламп и моделирует свет над низкой мебелью. FullHeightLightBlocker2D на prefab стен и створки регистрирует высокие прямоугольные препятствия; лампа получает только объекты своей сцены при изменении версии реестра. Дополнительные сценовые ссылки и ручной режим поддерживаются. Обход всей сцены в Update отсутствует. Компонент создаёт и освобождает индивидуальную временную cookie-маску, пересчитывая её при изменении геометрии или радиуса. Ceiling Lighting переключает потолочное/обычное плоское освещение с восстановлением исходной cookie и настроек теней. LocalLamp2D продолжает владеть яркостью/цветом/мерцанием, а фонарь — собственными тенями от мебели. Позиции ламп и столов не меняются, состояния AI и shared SO не затрагиваются. Это упрощение для 2D: конечные короткие тени по физической высоте мебели не рассчитываются.

CameraFollow2D подписывается на IFlashlightOpticsSource своего Target: ownership/optics events обновляют целевой размер, LateUpdate только сглаживает его; смена aspect/profile/target и повторное включение тоже пересчитывают цель. Configure/disable/destroy снимают подписки. CameraFramingProfile задаёт размер до находки фонаря, запас за лучом и сглаживание zoom; Orthographic Size учитывает меньшую сторону viewport. Общие значения прежних сцен (.4/.35) сохранены; MorgueRouteTest имеет отдельный профиль 2.4/.25/.4 и базовый луч 3.2. zoomVelocity принадлежит камере, asset профиля не мутирует. Новые модули не требуют знания камеры в коде лута.

Модули перенесены в `Features/Flashlight`: чистая личная FlashlightUpgradeModel, команды установки/восстановления, controller и фабрика через LevelContext. FlashlightUpgrades адаптирует прежний API/DTO и применяет оптику; FlashlightModuleValidation передаёт правила чистому валидатору. Повторяемые ID суммируют бонусы, count учитывает каждую установку; снижение лимита не ухудшает следующую находку, снимок проверяется до замены состояния. [Контракт переноса и реальные проверки камеры](../Reports/FlashlightUpgrades01.md).

FlashlightStateModel хранит личные владение/питание/оптику; ICommand-команды и controller передают их IFlashlightView. Flashlight2D сохраняет сценовые ссылки/сериализацию и принимает Input Actions. Наведение разделено на чистый FlashlightAimModel и Unity pivot environment; Covers считает прежнюю защитную область, отдельный obstruction adapter выполняет Physics2D.Linecast. FlashlightInstaller/фабрика подключены через LevelContext; startsOwned по умолчанию true сохраняет прежние сцены. FlashlightPickup2D остаётся адаптером proximity/LOS, а legacy FlashlightOwnership/AcquireFlashlightCommand — совместимым чистым helper API. [Границы и проверки](../Reports/FlashlightState02.md); тематический config-pass и остальная миграция не завершены.

Отдельные Update/FixedUpdate у камер, аудио и визуальных компонентов нормальны. Централизация без измерений не нужна: бюджетируются дорогие операции, не само имя метода.

## Проверки и связанные документы

Карты и доступ перенесены в `Features/AccessControl`: личные чистые модели, команды Add/Restore/CheckAccess, controller и фабрики через LevelContext. Компоненты PlayerAccessCards2D/DoorAccess2D сохраняют публичный API и служат Unity/View-адаптерами. Время считывателя поступает через IGameClock; независимые cooldown и постоянная разблокировка принадлежат модели. Прямое восстановление и player checkpoint проверяют ID карт до изменения состояния; null-коллекция поддерживается как legacy-пустая. Подробности и границы — [AccessControl01](../Reports/AccessControl01.md).

Двери используют внедряемый SceneRegistry уровня; статического Door2D.Active больше нет. Перенос движения створки и остальной интеракции ещё не завершён. Данные существующих экземпляров сохранены.

Контракт и авторинг: [Мир, фонарь, камера и интеракции](../Guides/LEVEL_AUTHORING.md). Проверки выбирать по [VALIDATION](../VALIDATION.md); прежние результаты — [Reports/ValidationIndex](../Reports/ValidationIndex.md). Полная архитектурная сверка — текущий этап [Roadmap](https://app.notion.com/p/3ff8d6dc06b681b6950bd8115222669c?pvs=204).

## Поверхности звука

GroundAudioSurface2D — авторенный Unity-адаптер зоны с BoxCollider2D, типом покрытия и приоритетом. Он регистрируется в SceneRegistry<IGroundAudioRegion> своего LevelContext, удаляется при OnDisable и получает ту же зависимость при динамическом создании. Статический список и выбор через активную сцену удалены. GroundAudioSurfaceQuery2D содержит чистый выбор: покрывающая точку зона с наибольшим приоритетом; равные сохраняют порядок регистрации; вне зон — Concrete. Коллайдер/активность остаются в адаптере. Изоляция/выбор проверяются без MonoBehaviour, реальный lifecycle и две сцены — отдельной Play-проверкой.
