# Сценарные маршруты врагов

TASK-ENCOUNTER-INTRO: одноразовые авторенные маршруты Сталкеров. В MorgueRouteTest четыре экземпляра ждут за первой дверью морга и после её полного открытия разбегаются к личным конечным точкам. Переиспользуемый запуск от фактического луча также поддержан.

## Поведение

Ожидание условия → необязательная реакция → последовательные точки → завершение и обычный Сталкер. `StartCondition` выбирается на экземпляре: `Flashlight` требует фактического луча; `DoorOpened` — полного открытия назначенной `TriggerDoor` из той же сцены. Начало анимации/попытка взаимодействия не запускают группу. Открытая при инициализации дверь тоже удовлетворяет условию. У дверной группы реакция 0 s; свет для старта не нужен. Закрытие двери и выключение света после запуска не отменяют бег, повторное открытие не перезапускает эпизод.

До завершения подавлены близость/LOS, внешняя активация агрессии, атака и агрессия от stagger. Пуля наносит обычный урон и даёт физическую реакцию; смерть немедленно отменяет маршрут. Фактическое освещение передаётся модели Сталкера отдельно от условия запуска: дверь не подменяет `Exposed`. При варианте `Flashlight` стены и закрытые двери блокируют стартовый луч; владения фонарём без освещения недостаточно. Нужен контакт в Light Fear Distance на весь Reaction Delay (.33/.45 s), затем обязательный ожоговый звук и остановка 1.4 s из StalkerBehaviourProfile. Глаз остаётся открыт первые 70% остановки, реальная доза постепенно растёт только под лучом. Species bridge передаёт эту длительность immutable settings маршрута вместо его общей Reaction Seconds. `DoorOpened` сохраняет собственные настройки и мгновенный старт группы без ожогового звука.

Прибытие освобождает сценарное управление в том же шаге; следующий физический шаг исполняет обычный brain. Само прибытие не выставляет агрессию. Без воздействий и с выключенным патрулём враг сидит на месте. Близкий видимый игрок, фонарь и попадание далее обрабатываются по обычным правилам, включая постоянную агрессию. Дополнительное событие уровня не требуется.

У компонента нет собственного Update/FixedUpdate: ShadowStalker2D вызывает либо маршрут, либо обычный StalkerController. Во время сценария личная StalkerModel получает фактическое наблюдение для состояния тела/света, но не отдаёт обычные решения движения или боя. Только существующий EnemyMotor2D управляет телом. Unity-мост использует прежние Recoiling/Retreating/Dead для кадра и голоса; общая модель маршрута не знает enum вида или двери. Подписка на окончание движения двери снимается при Dispose.

## Ответственность

| Данные/правило | Владелец |
|---|---|
| Неизменяемые скорость, реакция, допуск и застревание | ScriptedRouteProfile → ScriptedRouteSettings |
| Условие старта, дверь, ID эпизода и ссылки на точки | Экземпляр ScriptedStalkerRoute2D в сцене |
| Шаг, индекс точки, таймеры | Личный ScriptedRouteModel |
| Запуск/отмена | StartScriptedRouteCommand / AbortScriptedRouteCommand |
| Follow/скорость/остановка | ScriptedRouteController через IEnemyBrainMotor |
| Запрет обычных решений/передача | SetStalkerScriptedControlCommand и StalkerModel.IsScripted |
| Composition | ScriptedEncounterInstaller через EnemyInstaller в level scope |

Прогресс измеряется уменьшением расстояния до текущего маркера. При превышении времени без прогресса — Blocked и диагностическое предупреждение. Владение сохраняется, поиск пути продолжается; после прогресса снова Moving. Ошибка не считается завершением и не разрешает бой/телепортацию. Прибытие определяется фактической позицией в допуске.

## Авторинг

1. Поставить обычный ShadowStalker prefab и добавить ScriptedStalkerRoute2D нужному экземпляру. Остальным врагам компонент не требуется.
2. Назначить уникальный Encounter ID, профиль, Start Condition и массив Transform точек из той же сцены. Для Door Opened назначить Trigger Door. Позиции и ссылки остаются в уровне. Уже агрессивного врага вступительный сценарий не принимает.
3. Оставить на точках место под полный радиус тела; промежуточными маркерами задать сторону обхода. Обязательные ссылки и свободные конечные позиции проверяются на старте. Движение использует прежнюю навигацию и её бюджеты.
4. Выключить Patrol Enabled у вступительного экземпляра: после завершения он ждёт на месте, обычное обнаружение сохраняется.
5. Выделить врага: Scene View показывает линии, номера/стрелки и handles маркеров. Inspector показывает Current step, Next point и Controls actor. Редактировать при остановленном Play.

Пути и координаты первого эпизода — [инструкция сцены](../Guides/MORGUE_ROUTE_TEST.md#первый-сценарный-сталкер). Профиль группы — `Assets/EmergencyShift/Data/Encounters/DoorScatter.asset`; `IntroLightRetreat.asset` сохранён для маршрутов со световой реакцией.

## Границы

Перезапуск сцены создаёт новое состояние; повторное условие в одной попытке не запускает маршрут заново. Сценарный checkpoint payload не реализован. CaptureState/RestoreState сценарного Сталкера явно отклоняются, чтобы не записать обычный Dormant вместо прогресса маршрута. MorgueRouteTest остаётся без checkpoint-controller. Добавление маршрута в сохраняемый уровень требует отдельного payload/версии и проверки восстановления до первого AI tick.

Условие подбора фонаря перед открытием двери принадлежит отдельной TASK-DOOR-CONDITIONS. Оно не реализуется этим сценарием. Текущий Unity-мост подключает только Сталкера; другой вид требует собственного адаптера правил/представления, общая модель не привязана к комнате или двери.

Проверки и границы приёмки первой световой версии — [IntroEncounter01](../Reports/IntroEncounter01.md); дверной группы — [DoorScatter01](../Reports/DoorScatter01.md).
