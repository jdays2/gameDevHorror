# Оружие

Текущие модели, команды, управление и прицеливание оружия разделены; DI-фабрики создают личное состояние оружия и пуль. Общие readonly конфиги и native presentation/lifetime границы проверены; итоговая ревизия и область — [FinalVerification44](../Reports/FinalVerification44.md).

Принятая архитектура — [ADR-001](../Decisions/001-sod-architecture.md). Ниже описаны фактические границы; миграция остальных систем продолжается.

WeaponDefinition, MagazineWeaponDefinition и PumpShotgunDefinition настраиваются в Inspector и доступны runtime C# только через readonly getters. Прежние serialized names/defaults/content IDs/refs сохранены, модели получают immutable snapshots. Authoring пишет через SerializedObject, deliberate transient tests — через JsonUtility. Вложенные visual/audio SO ещё проходят общий config-pass. [Проверки](../Reports/WeaponDefinition20.md).

WeaponCatalog сохраняет serialized weapons refs внутри SO; C# читает DefinitionCount/DefinitionAt. Validate/Find/ToSettings отвергают missing definition/ID и duplicate IDs/selection slots до выбора, согласно прежнему pure catalog. Find при null array сохраняет null, ToSettings требует заданный массив; явный empty поддерживается. Editor/transient fixtures сохраняют исходные ссылки, save DTO weapons не менялся. [Контракт и стоимость](../Reports/WeaponCatalog21.md).

## Оружие: данные, наследование и композиция

`WeaponDefinition` хранит авторские числа и копирует их через `ToSettings` в проверенный неизменяемый `WeaponSettings`; его чистая фабрика создаёт `WeaponCycle`. Аналогичные MagazineWeaponSettings/PumpShotgunSettings задают варианты без ссылок на SO. Существующие CreateCycle-фасады только переводят авторский контент в эти данные. Текущий пистолет использует `MagazineWeaponDefinition` и `MagazineWeaponCycle` для атомарной замены магазина. `PumpShotgunCycle` теперь наследует общие loaded/reserve/отмену/снимок от MagazineWeaponCycle, добавляя собственную помпу и поштучный Tick. `PumpShotgunDefinition` наследует описание и создаёт соответствующий снимок; чистый PumpShotgunSettings задаёт веер/фабрику, `PumpShotgunCycle` расширяет общий расход патрона/cooldown помпой и поштучной зарядкой. Это две реальные вариации алгоритма. Новая числовая разновидность пистолета обходится новым asset; другой цикл потребует собственной реализации за тем же контрактом.

`WeaponInventory` получает чистые настройки и WeaponSettingsCatalog с общей проверкой ID/слотов; Unity-адаптер отдельно сопоставляет ID с визуальными asset. Инвентарь инкапсулирует словарь владения: свой cycle на каждый contentId, уникальный selectionSlot, независимые патроны и проверка снимка до изменения. Магазин включён в TotalAmmo, Reserve вычисляется как TotalAmmo − Loaded; вставка перемещает патрон, а не создаёт его. Общие ScriptableObject не изменяются во время игры.

Внешние изменения выполняют команды с CanExecute/CommandResult: fire/reload/cancel/add ammo/acquire/equip/replace/restore. Bool/int-фасады сохранены; проверенный Restore передаёт значения только после полной проверки, инвентарь сначала строит весь набор замены. Нечисловое внешнее время не меняет модель. Снимок помпы проверяет ограничения своей фазы и согласованность cue/магазина.

Разброс дробовика получает отдельный gameplay IRandomSource экземпляра PlayerWeapon через DI-фабрику. Cosmetic UnityEngine.Random вспышки/трассера не меняет направления. Прежняя треугольная плотность и ширина веера сохранены; RNG-state пока не сохраняется для replay. [Проверка BUG-010/018 и границы этапа](../Reports/WeaponModels01.md).

`WeaponController` автоматически запрашивает обычный `TryReload` у пустого активного магазина при наличии резерва: после выстрела и после Tick (в том числе после помпы). Допустимость и таймер операции остаются у cycle, поэтому поштучная зарядка и её прерывание сохраняются без проверки конкретного вида оружия. `AimReticle2D` отображает фазу Loading круговыми стрелками; собственное время UI относится только к вращению символа.

`PlayerWeapon2D` передаёт WeaponInputIntent в чистый WeaponController и отображает WeaponShotPlan. Контроллер использует IGameClock и команды; WeaponOwnerModel владеет инвентарём/RNG/номером залпа, фиксирует все направления до эффектов. WeaponAimEnvironment2D отдельно обслуживает вращение и Physics2D дула; авторская геометрия/PlayerAim/fallback фонаря остаются Unity-данными. WeaponInstaller/фабрика подключены в level scope, OnDisable/OnDestroy освобождают операции/подписки. [Проверка и границы](../Reports/WeaponController02.md). HUD читает свойства, не проверяет класс оружия. `BulletProjectile2D` использует Damageable2D без знания Сталкера. WeaponAudioProfile задаёт вариации и вид гильзы; отсутствие профиля сохраняет принятую библиотеку пистолета. ShotFired/Operation/CasingEjected разделяют выстрел, помпу, вставку и выброс. Аудио переиспользует существующие ограниченные голоса; одна громкая реакция на материал за залп, hit-cue Сталкера не чаще 0.05 с. Гильза хранит профиль выстрелившего оружия до приземления, даже после смены оружия.

PlayerCheckpoint2D пишет format3 с явными hasInventory/hasFlashlightState и владением фонарём, всеми contentId, патронами, фазами и оставшимися таймерами; ключ player.v1 сохранён. Старый format1 пистолета переносится в магазин min(capacity,total), остаток в резерв. Внутренний цикл пистолета format2 хранит также незавершённую замену магазина. Цикл дробовика сохранил format1 и совместимость. Летящие пули, гильзы и звук не сохраняются. Снимок не требует новых веток в общем файловом загрузчике.

## Проверки и связанные документы

Вспышка дула, попадание, blocked-muzzle impact и пули создаются через scoped ScenePrefabFactory, который внедряет зависимости и оставляет экземпляр в сцене источника. ShotEffect2D регистрируется только в своём level scope; visibility query дополнительно проверяет сцену. [Изоляция запросов света](../Reports/LightScopes22.md). Активность другой additive-сцены не меняет их lifetime; выгрузка источника удаляет замороженный эффект. [BUG-023: воспроизведение и проверка](../Reports/ProjectileOwnership10.md).

`Features/Projectiles` содержит immutable ProjectileFlightSettings, личную ProjectileFlightModel и LaunchProjectileCommand. Контроллер управляет шагом и завершает модель перед единственным hit callback; native BulletProjectile2D выполняет полный CircleCast, пропускает владельца/детей и триггеры, выбирает ближайший collider, передаёт урон через Damageable2D и показывает эффект. Геометрия и визуал не владеют дальностью/возрастом. Пуля не зависит от вида врага и видимости трассера. ProjectileInstaller подключён через WeaponInstaller, обе species используют прежний контракт урона.

ProjectileVisualProfile временно остаётся compatibility-конфигом ballistics/presentation: прежние bulletSpeed и visual fields сохранены, collisionRadius (.035) и maximumFlightSeconds (3) доступны в Inspector. ToFlightSettings копирует скорость/радиус/lifetime вместе с дальностью/уроном конкретного выстрела. Дальность ограничивается снизу .1 как раньше; истечение времени строго age > maximum, конец дальности удаляется следующим шагом. Летящие пули не сохраняются. [Проверки и стоимость](../Reports/ProjectileFlight16.md). Readonly/runtime API и validation обоих visual SO проверены: ShotVisualProfile отклоняет invalid/nested config до изменения эффекта и расхода патрона, authored values/refs сохранены. [BUG-028 и проверки](../Reports/VisualConfig31.md).

Гильза создаётся через ScenePrefabFactory и получает GroundAudioSurfaceQuery2D своего уровня до использования. Активная сторонняя сцена не меняет звук первого контакта. LastSurface показывает фактически выбранное покрытие; профиль выстрелившего оружия по-прежнему сохраняется до приземления. PlayerCasingEjector2D и шаги получают отдельные косметические RNG-потоки из composition; bounded pool гильз, физика, тайминги и библиотека звуков сохранены. Расстояние/cadence шагов выделены в личную модель с IGameClock/controller; PlayerFootsteps2D читает физическое перемещение и воспроизводит контакт. [Проверки и config-bridge](../Reports/PlayerFootsteps11.md). Гильза остаётся явным native FX/physics adapter; её launch tuning хранится в ShotVisualProfile, самостоятельная gameplay-модель для косметического движения не требуется.

Контракт и авторинг: [Оружие](../Weapons/README.md). Проверки выбирать по [VALIDATION](../VALIDATION.md); прежние результаты — [Reports/ValidationIndex](../Reports/ValidationIndex.md). Полная архитектурная сверка — текущий этап [Roadmap](https://app.notion.com/p/3ff8d6dc06b681b6950bd8115222669c?pvs=204).

ShotVisualProfile также задаёт casing port/clearance, side/forward/rise speed ranges и spin. PlayerCasingEjector2D остаётся bounded native FX adapter с отдельным cosmetic RNG, pool cursor ограничен размером коллекции. Прежние числа и порядок случайных выборов сохранены. PlayerWeapon2D делегирует acquire/ammo/equip/reload правилам inventory/controller; native barrel/physics/FX и authored references не требуют второй модели. [Итоговая сверка](../Reports/RefactorCompletion42.md).
